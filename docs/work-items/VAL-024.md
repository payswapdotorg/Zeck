## Architecture note (within the work order's allowed surfaces)

`src/**` and `spec/**` are untouched (forbidden by this work order). The tenant-isolation platform slice lives in `benchmarks/validation/platform/tenant-isolation.ts` (an allowed surface), mirroring the VAL-019/020/021/023 platform-slice pattern: the typed-rejection taxonomy as PURE derivations (`classifyPlatformRejection` — the authorities' own `PlatformError` codes: `TENANT_SCOPE_VIOLATION` for the execution store's locked-row checks, the create-time application/environment-ownership checks and the artifacts tenant namespace; `AUTHORIZATION_DENIED` for the scope resolver's membership boundary; `classifySdkRejection` — the public wire's own error codes + HTTP statuses, with `SCOPE_CHECKED_MISS` for the 404 indistinguishable miss another application's execution produces — identical to an unknown id, never a tenant oracle), the zero-data-disclosure discipline (`scanForForeignContent` + `redactForeignMarkers`: findings and redactions name the canary LABELS, never the other tenant's content — defense in depth at BOTH the seam and the driver: the driver re-redacts every journaled message so a leaky seam can never leak through the journal), the isolation-journal discipline (every driven probe journaled EXACTLY once through the lifecycle port with digest references and per-probe-distinct idempotency keys — the VAL-018 lesson), the bounded probe policy (a denied probe is NEVER retried — the scope checks are deterministic pre-dispatch machinery; a DISCLOSURE terminates the battery immediately), and the execution driver mirroring the VAL-019/020 drivers (authorize → plan → planning-decision BEFORE the first probe → queue → start → probes → verify → terminal: any disclosure or any failed criterion → FAILED — never a partial-success shortcut). **The honesty inversion this slice pins: the DENIAL is the pass condition** — a correctly-denied boundary COMPLETES the probe execution; a disclosed cross-tenant read/transition/artifact fetch FAILS honestly.

The app (`benchmarks/validation/apps/tenant-isolation/`) declares the isolation corpus (AC1): 10 rows — the four work-order-named families (cross-tenant read, cross-tenant transition, cross-tenant artifact fetch, cross-application state), the five AC6 discrimination families (cross-tenant create/application-id confusion, cross-tenant environment, cross-tenant planning, artifact adoption/artifact-ref probing, forged scope header) and the own-tenant control (the boundary must not over-deny). The corpus rows declare target **roles** (`foreign-execution`, `foreign-environment`, `foreign-application`, `foreign-artifact-digest`, `own-execution`, `own-artifact-digest`) — never run-time ids — so the corpus stays repository-reproducible and secret-free while the served world binds the actual seeded references. The app submits its probe task through the public SDK boundary and performs its own app-side SDK probe per row (create confusion, foreign-environment create, foreign read/cancel/events, the forged `X-Zeck-Application` selector via a second SDK client, the own-tenant control read), verifying the per-row typed-rejection contract with the PURE `verifyIsolationContract` (ordered observation sequence, zero disclosure, the miss-indistinguishability discipline: a scope-checked miss answers 404, never anything else).

## Issue findings and protocol

- **The control row's zero-foreign-rows criterion initially failed on the honest fake (found by this slice's own unit tests, fixed pre-commit).** The first formulation counted the rows returned by ANY scoped query; the control row's granted observations legitimately return the probe's OWN-namespace rows. Classification: criteria-derivation defect. Solution: the criterion counts only the FOREIGN-scoped queries (miss/disclosed observations); the granted control's rows are own-namespace rows, not foreign rows. Verification: the per-row driver test re-ran green. Impact: none beyond this slice.
- **Marker labels were initially dropped on denied observations (found by this slice's own unit tests, fixed pre-commit).** The first journal derivation read `foreignMarkerLabels` only from disclosed observations — a boundary that denied a probe but ECHOED the other tenant's content in its rejection message would have passed the zero-disclosure criterion (the message was redacted, but the finding was not recorded). Classification: criteria-derivation defect (the exact hole the defense-in-depth discipline forbids). Solution: the labels ride every observation kind, AND the driver re-scans + re-redacts every journaled message itself (a leaky seam can never leak through the journal). Verification: the new leaky-DENIED-message discrimination test (the journal carries the label, never the marker content). Impact: none beyond this slice.
- **The first draft of the discrimination suite clobbered WORK-002's existing `tests/discrimination/tenant-isolation.discrimination.test.ts` (found by the battery's diff review, fixed immediately).** The Write tool created the file at a colliding path, replacing the src-level cross-tenant-guard discrimination proof. Classification: worker authoring defect (outside the allowed surfaces — the file is a WORK-002 artifact, not a validation surface). Solution: the original file restored byte-identical from git (`git checkout` — verified zero diff); the VAL-024 suite renamed to `tenant-isolation-validation.discrimination.test.ts` per the precedent naming pattern (agentic-validation / security-validation / imagegen-validation). Verification: `git status` shows the original untouched; both suites pass side by side. Impact: none (nothing reached a commit).
- **The app-side 404 miss is observed as a typed denial, not a miss-kind observation (recorded calibration decision).** The public wire turns the scope-checked miss into a 404 `CAPABILITY_UNAVAILABLE` rejection — the app observes a typed DENIAL (code `SCOPE_CHECKED_MISS`, status 404); the miss KIND stays service-side (the null/zero-rows observation). The corpus pins both levels per row (app observations use `denied:SCOPE_CHECKED_MISS`; platform observations use `miss`). Recorded for the Lead's review; the miss-indistinguishability criterion enforces the 404 discipline at the app layer.
- **No live PG verification was possible in this sandbox** (no PostgreSQL server, no root — by design). The crown's service signatures are typechecked against the REAL contracts; the lifecycle binding, the planning-decision payload, the step-event journal and the ledger assertions mirror the live-verified VAL-020 crown binding exactly; the seam's expected typed rejections are the platform's own documented codes (the execution service's locked-row checks, the create-time ownership checks, the artifacts tenant namespace, the scope resolver's membership boundary — each covered by the platform's own PG suites). The Lead's credentialed re-run is the live verification. Any live divergence is an honest finding to record here.
- **The `inputArtifactRefs` create field is stored unvalidated at create time (recorded design observation, not a defect).** The refs are references, not data — they never disclose content and never authorize anything; the typed tenant-namespace violation fires at artifact FETCH/adoption (the artifacts service boundary the corpus probes). Recorded here for the Lead's review; a future slice may probe reference validation at create if the platform ever adds it.
