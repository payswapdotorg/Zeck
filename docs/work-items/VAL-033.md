## Architecture note (within the work order's allowed surfaces)

`src/**` and `spec/**` are untouched (forbidden by this work order). The equivalence platform slice lives in `benchmarks/validation/platform/equivalence-testing.ts` (an allowed surface), mirroring the VAL-030/031/032 platform-slice pattern. The slice's PURE derivations: `deriveReplacementIsolation` (the replacement's declared capability set vs its granted isolation surface — an undeclared capability or an ungranted demand is a containment VIOLATION that FAILs and names the direction), `deriveDifferentialEquivalence` (the differential oracle: equality is NOT required for semantic outputs, but the acceptance criterion must be EXPLICIT and mechanically evaluated — a stated-but-never-checked criterion FAILs, a checkable-but-unchecked case FAILs with the case named, a divergence is recorded case-by-case honestly, never smoothed), `deriveProvenanceCompleteness` (the verdict must cite its source proposal — a registry member — AND the full differential population: the historical replay identities plus the pinned adversarial cases; a phantom citation, a mismatched proposal, a missing adversarial case or a replay-identity subset FAILs), `deriveStageDiscipline` (the lifecycle walk `proposed → offline-replayed → differentially-evaluated` ONLY — any jump past the differentially-evaluated stage, a skipped rung, an evidence-less transition or a walk starting from a non-proposed candidate FAILs), the append-only lifecycle ledger port (the equivalence run APPENDS transitions, never rewrites a registry entry), `deriveHonestReplacementRun`, the digest discipline (FNV-1a, payload-free), `deriveEquivalenceRowCriteria` (the per-row mechanical verdict), and `verifyEquivalenceTestingAppContract` (the app-boundary oracle).

**The equivalence honesty invariants this slice pins:** every acceptance criterion is stated AND checked; divergences are recorded case-by-case (an honest FAILED row is a legitimate terminal — never smoothed into a pass, and a satisfied case claimed non-equivalent is a false-divergence claim that FAILs); provenance is complete (proposal citation + full population) or the verdict FAILs; the lifecycle advances one evidenced rung at a time and NEVER beyond `differentially-evaluated` (shadow/canary/promotion are VAL-034/035's scope); the VAL-032 registry is read-only input (a different-content commit under a recorded identity THROWS); synthesized replacements run isolated (each escape direction is a named violation); evidence carries payload DIGESTS, never payload bytes.

The app (`benchmarks/validation/apps/equivalence-testing/`) declares the corpus (AC1): 12 offline rows + 1 env-gated live row. Per row the corpus declares the source proposal (a VAL-032 registry identity), the replacement shape (deterministic-function / split-preprocessing / retrieval-pipeline / reusable-tool / removed-call), the differential population (cited historical replay inputs + pinned adversarial cases), the explicit acceptance criterion, and the expected verdict (equivalence-pass / honest divergence / honest refusal). The corpus includes the four positive replacement shapes (one per VAL-032 candidate kind), the honest-divergence row (the removed-call replacement diverges on all 10 cases — FAILED honestly, never smoothed), the two honest refusals (unregistered proposal; single-replay evidence), and six equivalence-probe rows (broken-provenance / partial-population / unchecked-criterion / divergence-smoothing / skipped-stage / containment-escape) whose populations are pinned now and whose adversarial fake-runtime/fake-ledger variants FAIL mechanically in the discrimination suites. The app rides the public SDK boundary (`createZeckClient` — no `src/**` import), drives each row's equivalence run through the harness's submit seam, reads the verdict + lifecycle landing back (RE-DERIVING the contract, never trusting the platform's claim), and verifies its own contract with the PURE `verifyEquivalenceTestingAppContract`.
