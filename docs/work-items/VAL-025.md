### Review finding (live-only defect, caught by the Lead's credentialed re-run)

The crown's first live run FAILED on the second live row with the platform's honest typed `PROVIDER_ERROR: credential material failed integrity verification` (the credential vault failing CLOSED on a cross-key envelope):

- **Root cause:** the live loop called `buildLiveDispatch` PER live row, and each call minted a FRESH random master key (`generateMasterKey()`) while registering the SAME connection label (`val-025-openrouter`) on the same application. The platform's label-uniqueness convergence (an identical re-registration returns the EXISTING connection and destroys the stray vault row — `ConnectionService.registerConnection`) then handed the second row the FIRST row's connection, whose credential envelope was sealed under the first row's master key; the second gateway's vault materialized it under the second key → AES-GCM integrity failure.
