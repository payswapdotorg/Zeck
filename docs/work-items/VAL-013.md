## Issue findings and protocol

- **Checkpoint-event assertion defect (found by the first live run, fixed before commit).** The initial per-task assertion required `checkpoint events == job.items.length` — WRONG for the corrupted-checkpoint row, whose correct behavior is to STOP at the corruption boundary (1 checkpoint, progress never trusted past it). Classification: validation-defect (assertion semantics). Fix: the ledger must mirror the driver's checkpoints exactly, and healthy runs must reach `items.length` (both asserted). Verification: rerun green with the corruption row failing exactly as the corpus declares.
- **Stale-worker discrimination made REAL (design iteration, pre-commit).** The first version journaled the denial without actually attempting the invalid transition; the final version attempts a genuine `resume` on the RUNNING execution — the REAL state machine rejects it (resume is legal only from WAITING_* states), the rejection is caught and journaled. The unit fake enforces the same rule (a miniature state machine). Classification: harness hardening.
- **Transient flake:** the pre-existing `pg-database-port` pool-bounds test failed once under full-suite parallel load and passed on rerun (recorded; unrelated to this Work Order's surfaces).
