## Design decisions (architect-review pointers)

1. **The API is a projection/command facade over the authorities (§6).** Every route delegates: creation/cancellation → the executions service (the single write path — cancellation goes THROUGH `transition({command: "cancel"})`, M26); agent inventory → the registry's read methods; the API NEVER writes execution/agent tables (the architecture gate proves no SQL exists anywhere in `src/api/`, `sdk/`, `cli/`, `apps/` — M13/M14). The composition is dependency-injected: `createApiServer(deps)` receives the module services through their PUBLIC interfaces; the production wiring (SQL stores over the pg DatabasePort) is the composition root's concern — the api layer imports module public barrels + shared ONLY (the scanner-pinned api-boundary).
2. **Server-side scope derivation is the M1/M2/M3 protection.** The transport authenticates ONCE per request (the injectable credential seam → the auth module's `Principal` — "an already-authenticated actor reference"); the effective application/tenant scope is ALWAYS derived by the auth module's scope resolver from durable membership/ownership rows. There is no code path that reads a tenant from the request; the closed create vocabulary rejects client tenant/provider keys outright; scope-checked misses are 404s indistinguishable from missing (no tenant leak).
3. **The secret-safety boundary is constructive, not advisory (M4–M8).** Every response body is built FIELD BY FIELD in `serialization.ts` (allowlist construction — a mutated domain record with an added secret field cannot leak because the serializer never spreads); a deep scrub guard redacts secret-shaped keys at every depth (defense in depth for caller-provided task/metadata payloads); the webhook payloads are scrubbed before delivery; the signing secret is injected as an opaque string and appears in no response, header, payload or log. The architecture gate pins the allowlist discipline (a spread mutant is detected).
4. **The wire contract has ONE source (API-002 + drift-proofing).** The public shapes live in `src/shared/wire.ts` (imported by the api transport — api → shared is the sanctioned direction — and re-exported by the SDK). The SDK adds only client behavior (fetch client, signature verification, dedupe guidance). The alternative (twin type definitions kept in sync by convention) is exactly the drift surface this design eliminates.
5. **Idempotency is DELEGATED, never duplicated (§10).** The api layer adds NO idempotency store: POST routes require the `Idempotency-Key` header and pass it to the executions authority, whose `(application, operation, key, fingerprint)` arbitration already converges/fails-closed. The PG proofs (concurrent duplicate POSTs → one durable row; same key + different fingerprint → 409) run through the REAL HTTP surface.
6. **Webhooks are signed, versioned and honestly retryable (API-004).** The envelope carries the full identity set (schema version, execution, durable event identity, sequence, attempt, timestamps); the signature is HMAC-SHA256 over a DOCUMENTED canonical serialization (the SDK's verifier and the CLI's docs share the exact basis — a receiver never trusts an unsigned webhook, M9); retries rebuild + re-sign the envelope per attempt so receivers can always tell WHICH attempt they see; the receiver-side dedupe contract is `eventId` (ack replays — M10). Durable delivery state (a persisted attempt journal) is the webhooks module's surface — outside the declared surfaces — and is disclosed as a limitation, NOT silently improvised in the transport (the api layer is transport-only per the frozen architecture).
7. **The dashboard is a projection, never truth (M24).** It holds no state: every render is a live read through the SDK client; the ONE governed command (cancel) goes through the API's cancel route (the lifecycle authority validates it). HTML-escaping on every interpolation (M7).
8. **The public error model is the canonical taxonomy, closed (M25).** `PlatformError` codes map to a total, deterministic status table; the transport's own input failures use canonical codes; unknown errors fail closed to a disclosure-free 500 (originals logged server-side only — never serialized; the mapper scans clean of stack/cause serialization). The status mapping never leaks SQL, host paths or provider internals.
9. **Provider neutrality is scanner-enforced (M17/M18).** The provider-identifier scan runs over `src/api/`, `sdk/`, `cli/`, `apps/` (the architecture gate); the SDK rejects provider-selection client-side; the CLI has no provider command; route summaries carry provider/model as opaque neutral strings exactly like the policy vocabulary.

## Limitations

- The production composition root (constructing SQL stores over the pg `DatabasePort`, wiring the platform secret store for signing secrets) is NOT part of this branch: the executions module's public barrel does not export its SQL fabric, and `src/platform/db/` has no production pg adapter (the harness note: "the production adapter arrives with the Work Order that owns that surface"). The api layer ships as the dependency-injected transport; the tests wire the REAL SQL stores directly (the established test-composition pattern). A production `main.ts` entry needs a composition Work Order or an additive executions-barrel export — an amendment decision for the architect.
- Webhook delivery retry state is in-flight transport state: a durable delivery journal (persisted attempts, dead-letter queues, redelivery windows) belongs to the webhooks module's durable surface, which is outside this Work Order's declared surfaces. The transport semantics (signature, envelope, attempt accounting, bounded retry, receiver guidance) are complete and proven.
- The agent inventory enumeration seam (`listAgentIdsOfApplication`) is injected: the agents module's public registry exposes per-id/slug getters but no bulk listing (ACP-001's catalog surface). The PG world wires it over the real agents table; a registry-level listing method would be an additive agents-module change (an amendment decision).
- The API's route/cost projections read the canonical event ledger; settled cost facts surface only when the executions ledger carries them (the result package reports null cost rather than a fabricated number until the budgets authority settles through its own surface).
- The dashboard is server-rendered HTML over the SDK (no frontend framework — no new runtime dependencies beyond fastify); rich client-side interactivity is future experience-surface work.
- CI runs the architecture/unit/integration suites but not the real-PG suites (the standing WORK-002 flag: no PostgreSQL service in CI); PG proofs are local-verified against real PostgreSQL 17.11 and recorded above.
- Transport authentication is the injected `authenticate` seam (bearer-token authenticator provided); production credential transport (per-application API keys with rotation) is a future auth-surface Work Order — the seam is the frozen contract ("an already-authenticated actor reference").
