## The transport/correlation model (what the machinery actually does)

- **Queue port** (`src/platform/queue/port.ts`): publish / pull / settle over opaque bodies and lease handles; typed `QueueTransportError` classified `transient | permanent`; the bounded `QueueRetryPolicy` (publish/delivery/replay budgets + deterministic linear backoff, all repository-configured and validated fail-closed); the `GovernedDispatchEffect` seam; the correlation vocabulary and deterministic key derivation. **No vendor vocabulary exists on the port** (pinned by architecture B2).
- **Cloudflare Queues adapter** (`src/platform/queue/cloudflare-queues.ts`): the documented REST protocol (publish `POST …/messages` body `{"body":…}`; pull `POST …/messages/poll` `{visibility_timeout_ms,batch_size}` → `result.messages[{id,lease_id,body,timestamp_ms,attempts,metadata}]`; settle `POST …/messages/ack` `{acks:[{lease_id}],retries:[{lease_id}]}`), Bearer auth, 401/403/404 → permanent, 429/5xx/network/timeout → transient, malformed envelopes fail closed, the token never enters an error, plus the round-trip `probe()` — **corrected per the PR #6 review: it runs exclusively on the DEDICATED operator-owned probe queue (`ZECK_PROBE_QUEUE_ID`) and acknowledges exactly its own message** (see the correction section). Zero new SDK dependencies (plain fetch — the sanctioned runtime import set stays `fastify, pg`).
- **Durable dispatch** (`correlation.ts` + `dispatcher.ts` + migration `0026_queue_transport.sql`): the PostgreSQL correlation record (`queue_transport.dispatch_envelopes`) commits **BEFORE** the external publish (mid-flight probe proof); the deterministic correlation key `execution-dispatch:<executionId>[:replay-N]`; the pointer payload (ids + provenance only — secret-free, sha256-digested); bounded publish with per-invocation budget; transient exhaustion → **backlogged** (recoverable via `republishPending`, reads PostgreSQL authority only); permanent rejection → **dead-lettered**; every attempt is append-only evidence (`transport_attempts`); every bounded failure is an explicit `dead_letters` row.
- **Idempotent consumption** (`consumer.ts` + the executions-module `transport-effect.ts` adapter): deliveries resolve the authoritative envelope from PostgreSQL FIRST (unbacked messages are refused + acked — provider state is never authority); binding + digest mismatches dead-letter fail-closed (tenant isolation included); the governed effect re-enters the **existing single execution write path** (`start` transition) with the deterministic consume key `queue-consume:<correlationKey>` — duplicate delivery, consumer restart, crash-before/around/after mutation and ack loss all converge to **exactly one authoritative effect** through the executions idempotency arbitration; governed rejections dead-letter with the reason; transient failures re-queue inside the delivery budget, exhaustion dead-letters explicitly.
- **Physical schema discipline** (migration 0026): the transport state vocabulary is CHECK-bound and **disjoint from the 14-state execution vocabulary** (terminal `consumed`/`dead-lettered` — deliberately renamed away from any execution word); the legal progress transitions are trigger-enforced; terminal rows are immutable; append-only evidence tables are trigger-enforced; tenant/execution bindings are real composite FKs (a correlation record for a nonexistent execution is unrepresentable).

## PR #6 correction (Architect review — the probe authority-boundary defect)

The Architect review of PR #6 (comment `5554345724`, CHANGES REQUESTED) found a **real production-safety defect**: `src/platform/queue/cloudflare-queues.ts` implemented `probe()` by polling the configured **execution** queue and then **ACKing every leased message that was not the probe message** — the smoke probe could lease unrelated execution deliveries and permanently acknowledge them without passing through the authoritative consumer: potential execution loss, violating the queue-as-transport-only authority boundary.

**The correction (commit directly below this doc's commit):**

1. **Dedicated operator-owned probe queue.** `probe()` NEVER targets the execution queue. Its publish → pull → ack round trip runs on a dedicated probe queue (`ZECK_PROBE_QUEUE_ID`, new ordinary non-secret variable) that carries no application workload and is not part of the environment's authoritative resource inventory (documented in `deploy/README.md`, including provisioning: HTTP pull consumer + the same token scopes). The probe never publishes into, pulls from, settles against or even observes the execution queue — probe traffic can physically never mix with execution deliveries.
2. **Exact-own-message settlement discipline.** The probe acknowledges **exactly the one message it published in that run** (exact probe-tag match). Anything else it happens to lease — an execution delivery, another probe's message, foreign noise — is never acknowledged and never re-queued (releasing via retries would consume the provider's per-message attempt budget and could push real messages past their retry ceiling into deletion); the lease expires — the transport's documented crash-recovery mechanism — and the message returns for its rightful consumer. Unrelated workload is unconsumable by construction, even on a contaminated or misconfigured probe queue.
3. **Fail-closed guards.** `probe()` without a probe queue refuses with the exact variable name (`ZECK_PROBE_QUEUE_ID is not set…never targets the execution queue`); a probe queue equal to the execution queue is rejected at configuration validation **and** again at probe time; a malformed probe queue id is rejected fail-closed; the `deploy:queue -- probe` command fails closed with the same exact message; `deploy:smoke`'s async-transport concern reports the honest `unavailable` with the exact missing-variable reason.
4. **The second instance of the identical defective pattern** was found in the gated live suite's port-flow test (its marker-search loop ACKed every unrelated leased message "so the test leases nothing it does not own") — retargeted to the probe queue with the same never-settle-foreign discipline; test traffic never enters the execution queue.

**Regression proof (the review's explicit requirement — `tests/integration/queue/cloudflare-protocol.test.ts`, real HTTP, execution-shaped deliveries seeded on the queues):**

- **REGRESSION (unrelated messages cannot be ACKed by the probe):** a probe queue deliberately contaminated with three execution-dispatch pointer payloads plus a foreign (earlier probe's) message — the probe acknowledges **exactly one** message (its own, fresh unique tag); every unrelated execution delivery and the foreign probe message remain pending and deliverable; the single wire `ack` carries exactly one ack entry and zero retries.
- **Boundary (zero execution-queue contact):** with real workload seeded on the execution queue, the probe issues **ZERO requests** against the execution queue's REST path (the workload is never even leased); the workload is byte-identical afterwards; the probe's own message is cleaned up on the probe queue.
- **Discrimination (weakened forms rejected):** no probe queue → `probe()` fails closed naming `ZECK_PROBE_QUEUE_ID` before any wire call; probe queue == execution queue → rejected at configuration validation; malformed probe queue id → rejected. Pinned in both the protocol suite and the discrimination suite (mutation-proven rejection of the weakened forms).
- The fake protocol server was extended to host both queues (execution + probe) on one account with per-queue seeding and per-queue pending/settled state accessors — requests to any other queue id answer 404 (the adapter cannot wander).

**Re-verification executed for the correction:** `deploy:queue -- probe` (fail-closed with the exact variable name), `deploy:smoke` three honest directions (missing probe queue → the exact `ZECK_PROBE_QUEUE_ID` unavailability; full materialization with an invalid token → the REAL public API answered 401 and the probe failed closed honestly; probe queue == execution queue → the configuration rejection), and the full regression battery re-run at the corrected final head (below).
