## Issue findings and protocol

- **[recorded design decision] The startup-inclusion oracle recomputes the startup share rather than testing "warm-up > 0 ⇒ share > 0".** A warm-up short enough to price below 1µ$ honestly rounds to zero (the REAL process substrate's cold start is exactly this class — a real `/bin/echo` probe completes in single-digit milliseconds, pricing below a micro-dollar at the pinned fleet rate). The hiding catch therefore fires when a PRICED warm-up (recomputed > 0) is zeroed or a claim disagrees — never on honest sub-micro-USD rounding. Trade-off: a hypothetical fleet priced so low that a material warm-up rounds to 0µ$ would not trip the facts-side catch — the claim-side and decomposition catches still hold, and the integrity oracle binds the exact shares. Recorded for the Lead's review.
- **[recorded design decision] The live lane's arm-side sufficiency check applies to the recorded lanes only.** The live row's arm set is a rail declaration (the VAL-044 live arm rows carry no recorded replay — their extractor output is 0 runs by construction), so the confidence oracle's arm-sample check would spuriously starve the live row. The live row's statistical minimums are its own (`minimumWindows` 1, `minimumRunsPerWindow` 3 — the measured workload units). The VAL-044 live-precedent digest-disagreed posture is NOT repeated: VAL-046's live lane composes the measured facts directly (the live-input composition lane VAL-044 deferred).
- **[recorded design decision] The recorded telemetry's served-workload counts re-derive from the arm corpora at EVERY derivation** (module load, verification, digest computation) — the run provenance is never copied into the windows. A future arm-corpus correction therefore propagates mechanically (and breaks window digests loudly, the content-addressing catch) rather than silently diverging. Trade-off: the window digests are stable only as long as the arm corpora are — acceptable, they are the recorded basis.
- **The substrate lifecycle timing facts are pinned telemetry, not re-derived** — no prior recording of substrate lifecycle timings exists in the program (the arm corpora recorded model-rail facts; VAL-022 recorded failure shapes, not priced windows). This slice records them as its pinned corpus (the same discipline every recorded corpus in the program uses); the live row is the only place new lifecycle measurements happen. The re-derivation-over-recorded-telemetry discipline applies WITHIN the slice (digests + field equality against the pinned telemetry).
- **No PG-backed crown run was possible in this sandbox** (no PostgreSQL — by design). The lifecycle binding and the ledger assertions mirror the live-proven VAL-044 crown precedent exactly; the Lead's credentialed re-run is the live verification. Any live divergence is an honest finding to record here.
