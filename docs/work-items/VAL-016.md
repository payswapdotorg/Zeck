## Issue findings and protocol

- **Wrong-modality tasks with foreign prompt keys threw NOT-RUN instead of failing wrong-modality (found by this slice's own discrimination test, fixed pre-commit).** The first driver draft derived the dispatch plan before any vocabulary check, so a foreign-kind task carrying a foreign prompt key (`{kind: "generate-image", prompt: "img-prompt-001"}`) aborted at materialization as a NOT-RUN boundary — mislabeling a MODALITY problem as a FIXTURE-COVERAGE problem. Classification: semantics defect (driver ordering). Solution: the driver now checks the task KIND before plan derivation — a foreign kind completes as an honest wrong-modality FAILED run through the canonical lifecycle (no planning decision: nothing was plannable; no network effect), while absent fixtures of the CORRECT kind remain the thrown NOT-RUN boundary. Verification: the discrimination test (zero transport calls, `provider-failure:wrong-modality`) and a dedicated driver unit test asserting the transition order without a planning-decision. Impact: none (found before any dispatch path ran).
- **A type-narrowing escape in the rail's terminal return (found by typecheck, fixed pre-commit).** The post-loop state union still admitted `submitted` (logically unreachable after task issuance), which the compiler correctly refused to destructure. Classification: type-safety defect. Solution: an explicit `failed` branch plus an honest `lifecycle-violation` failure for the unreachable `submitted` case (fail loudly, never fabricate a completion). Verification: `bun run typecheck`.
- **`readonly` modifiers inside an `as const` object literal (found by typecheck, fixed pre-commit).** `VIDEO_BYTE_BOUNDS` declared property-level `readonly` in a plain literal — invalid TypeScript (the `as const` assertion already freezes it). Classification: syntax defect. Solution: dropped the redundant modifiers. Verification: `bun run typecheck`.
- **The D1 discrimination's zero-network assertion initially measured an unused transport (found by lint's unused-variable warning, fixed pre-commit).** The first draft built a scripted transport for the digest-mismatch case but asserted zero calls against it while the tampered binding rode a different fake rail — the assertion was vacuous. Classification: test-strength defect. Solution: the tampered binding now rides the scripted transport itself, so `calls.length === 0` is the genuine network-effect truth. Verification: the discrimination suite.
- **Rail-reported duration/dimension fields on the live rail (recorded risk, by design).** The verification enforces the rail-reported duration/dimension bounds exactly WHERE the rail reports them; the wan2.2 task-poll output shapes read (`video_url`, `video_duration`, `resolution`, `results[].url`) are implemented per the work order's design guidance and verified against controlled fakes. If the live rail reports nothing, the criteria are honestly absent (never guessed); if it reports different field names, the honest gap surfaces in the Lead's re-run as a recorded finding.
- **Declared size support on the live rail (recorded risk, by design).** The healthy rows declare `1280*720` / `720*1280` (720p class, rail-supported shapes for the declared aspects) and the dimension criterion (where reported) requires exact equality — an unsupported size would fail honestly (a visible 400 or a mechanical dimension mismatch, never a silent pass). Classification: calibration decision; a live quantization surfaces honestly in the Lead's re-run.
- **Zero-duration edge rows are pre-dispatch rejections (by design, mirroring the corpus).** The corpus's zero-seconds edge row expects FAILED/FAIL; the platform rejects a zero-or-negative duration BEFORE any paid dispatch (zero transport calls — discrimination-tested) rather than gambling a paid dispatch on the provider's duration handling. Both the standalone row AND the jobs app's edge item ride this contract (the job's FAILED terminal is the honest propagation of that rejection — never a fabricated job failure or a dropped item).
- **No live provider verification was possible in this sandbox** (no credentials, by design). The Lead's credentialed re-run is the live verification; any live shape divergence is an honest finding to record here.
