## Architecture note (within the work order's allowed surfaces)

`src/**` and `spec/**` are untouched (forbidden by this work order). The baseline-freeze platform slice lives in `benchmarks/validation/platform/longitudinal-baseline.ts` (an allowed surface), mirroring the VAL-021/024/025/026 platform-slice pattern. The slice's PURE derivations: `deriveFreezeIntegrity` (the manifest digest agreement — any mutation of a frozen app version, workload revision or recorded trajectory FAILS; a tamperer who edits the steps AND re-declares the digest is caught by the equivalence-class membership backstop; an EDIT of a committed registry pin is refused by the honest registry; an appended correction passes as a NEW revision, never an edit — the registry is append-only), `deriveRerunEquivalence` (a control re-run over the deterministic fixtures reproduces the recorded trajectory-digest equivalence class — a drifting re-run FAILS; `trajectoryClassOf` defines the class), `deriveLedgerExactlyOnce` (every control run is ONE immutable longitudinal-experiment identity per the VAL-007 discipline — a LEAKY duplicate identity FAILS, a re-run that MINTS a second identity FAILS, a re-observation with DRIFTED identity content is REFUSED), `deriveInertLearningCompliance` (the control semantics: learning explicitly INERT — the three pinned contamination kinds `trajectory-reuse`, `caching-hint`, `competence-shortcut` each FAIL; the inert control is the reference arm every later learning claim must beat), `deriveAccountingHonesty`, `deriveTerminalCriteriaAgreement` (the anyFail→FAILED discipline re-pinned locally), and the FNV-1a digest discipline (deterministic, payload-free).

**The freeze honesty invariants this slice pins:** a drifting baseline is unrepresentable (freeze integrity on every leg); a control re-run reproduces the recorded equivalence class (trajectory drift between re-runs FAILS); every control run is exactly ONE immutable ledger identity (duplication FAILS both as a leaky ledger and as a minted re-run); learning is INERT in the control arm (each contamination kind is mechanically caught — the trajectory shape alone never catches a caching hint, the dispatch-demand ledger does); the registry is append-only (a correction is a NEW revision, never an edit of a committed pin); economics and latency are measured, never estimated; evidence carries payload DIGESTS, never payload bytes.

The app (`benchmarks/validation/apps/longitudinal-baseline/`) declares the corpus (AC1): 10 offline rows + 1 env-gated live row. Per row the corpus declares the baseline manifest entry (app digest + workload revision — content-addressed, digests over the pinned artifacts, never the artifacts copied), the expected terminal, and the trajectory-digest equivalence class the control run must reproduce. The corpus includes three contamination-probe rows (reuse/caching-hint/competence-shortcut) whose honest controls prove the inert arm, the guard-rejected row (FAILED honestly, zero dispatches), and the re-run-equivalence row (the recorded trajectory REPLAYED with zero new journal events). The app rides the public SDK boundary (`createZeckClient` — no `src/**` import), fires every row's control submission through the harness's submit seam, performs the control re-run on the re-run row, and verifies its own contract with the PURE `verifyLongitudinalBaselineAppContract`.
