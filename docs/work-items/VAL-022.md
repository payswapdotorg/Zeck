## Issue findings and protocol

- **The bounded executor's first draft lost the observation race on SETTLED runs (found by this slice's own unit tests, fixed pre-commit).** The seam promise chain was one `.then` DEEPER than the timer chain (the `.catch` adapter-error fold), so an immediate test timer won the race against a synchronously-settling run — every healthy fixture classified as `sandbox-lost`. Classification: platform-driver defect (the race asymmetry). Solution: the two-argument `.then(onFulfilled, onRejected)` — the two chains are now SYMMETRIC in depth (one `.then` each, the VAL-020 tool-executor discipline), and the adapter-error fold rides the same link (an adapter throw still settles as `adapter-error` — never a loss). Verification: the settled-wins/lost-wins/adapter-error executor unit tests + every driver row test. Impact: none beyond this slice (found before any PG path ran).
- **The bounded-retry criterion mis-read zero-attempt readiness refusals (found by this slice's own unit tests, fixed pre-commit).** The `readiness-refused-terminal` row (zero dispatch attempts — the never-dispatch-to-unready discipline) failed the non-retryable-single check, which demanded exactly one attempt for a non-retryable injected class. Classification: test-oracle defect. Solution: the check is `attempts.length <= 1` (AT MOST one dispatch attempt — zero when readiness refused pre-dispatch; never a retry after a non-retryable failure; the OOM-with-retries discrimination still FAILs). Verification: the refused-row driver test + the OOM-retry discrimination test. Impact: none.
- **The live rows initially shared one substrate id (found by oracle tracing before any run, fixed pre-commit).** The three live rows would have shared the registry streak (the exit row would have spuriously "quarantined" the live substrate at the timeout row's streak). Classification: fixture-design defect. Solution: each live row drives its OWN substrate id (the cross-execution quarantine carry is the offline quarantine row's contract — the live rows verify the REAL adapter path). Verification: the corpus consistency test + the live-row oracles. Impact: none.
- **The crown's transition-order reconstruction initially counted the planning-decision event as a transition (found by tracing the REAL event envelope, fixed pre-commit).** The REAL `recordPlanningDecision` appends an event with command `plan` and cause `planning-decision` (its own envelope), so the raw command list shows two `plan` entries. Classification: test-harness calibration defect. Solution: the reconstruction filters cause `planning-decision` and asserts exactly one decision envelope per execution, landing BEFORE the queue transition (raw event order). Verification: the crown's ledger assertions (the Lead's re-run). Impact: none.
- **No PG-backed crown run and no live crown run was possible in this sandbox** (no PostgreSQL — verified directly, by design). The lifecycle binding, the ledger assertions and the REAL adapter binding mirror the live-proven VAL-019/020/21 crown precedents exactly; the REAL process adapter path itself was smoke-verified directly in this sandbox (probe → ready; healthy → exit 0; 250 ms deadline → the REAL SIGKILL with the timeout class; exit 7 → the exit-code fold) — a throwaway script, recorded here as a finding note, not as committed evidence. The Lead's credentialed re-run is the live verification. Any live divergence is an honest finding to record here.
- **Live substrate-failure coercion is a structural NOT RUN boundary (recorded design decision, per the work order's own framing).** Mid-execution loss and OOM coercion cannot be produced on demand on a REAL healthy substrate; the injection points are the adapter seams, and the offline corpus covers both shapes deterministically at those seams.
