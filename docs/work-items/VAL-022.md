## Architecture note (within the work order's allowed surfaces)

`src/**` and `spec/**` are untouched (forbidden by this work order; verified — the delivery is 100% additive, six new paths, zero edits). The substrate-failure platform slice lives in `benchmarks/validation/platform/substrate-failure.ts` (an allowed surface), mirroring the VAL-019/020/021 platform-slice pattern:

- **The fact-driven taxonomy (PURE derivations).** `classifySubstrateFailure` derives the substrate-failure class from the adapter observation with the substrate's OWN facts winning over the adapter's failure-class label: an OOM verdict (`oomKilled: true`, the container family's OOMKilled evidence) or a SIGKILL exit (137) while the deadline did NOT elapse is `resource-exhausted` — NON-retryable, regardless of whether the adapter labeled it `timeout` or `sandbox-execution` (the misattributed OOM-vs-timeout discrimination; an OOM reproduces deterministically at the same admitted resource profile, so a retry would fabricate an outcome the substrate cannot honestly produce); a `timeout` token confirmed by `deadlineElapsed: true` (the runtime's own timer) is `substrate-timeout` — retryable; an `adapter-error` carrying the closed-sandbox evidence (`sandboxLost: true`) is `sandbox-lost` — retryable with a fresh sandbox; `sandbox-execution` without OOM evidence is `task-failure` — the TASK layer (the substrate is never blamed for the task's own non-zero exit, and it never strikes); `runtime-unavailable` is the platform's own fail-closed unwired-substrate posture. The layer table (`substrate | task | platform`) and the retryable set (exactly `readiness-refused | sandbox-lost | substrate-timeout`) are pure lookups.
- **The strike/quarantine state machine (PURE).** Terminal substrate-layer submission failures strike (a task failure never does; a recovered submission closes the circuit — `applySuccess`); TWO strikes engage the quarantine with a cool-down window (60s on the pinned injectable clock; a re-strike never extends the window); `deriveGateVerdict` checks the quarantine BEFORE the probe — a quarantined substrate is never even probed, never dispatched (the mechanical quarantine-bypass protection).
- **The driver** (`driveSubstrateFailureExecution`) mirrors the VAL-019/020 drivers (authorize → plan → planning-decision BEFORE the first dispatch → queue → start → the gated attempt loop → verify → terminal: a failure outcome or any failed criterion → FAILED — never a partial-success shortcut). The attempt loop: the quarantine gate first (zero substrate contact), then the registry (an unwired kind fails closed, journal-then-fail), then the readiness probe (never dispatch to an unready substrate — the probe verdict is journaled per attempt), then the dispatch on a FRESH sandbox identity (`${executionId}-sbx-${attempt}` — a lost/timed-out sandbox is never re-entered), then the fact-driven classification, the journal (exactly once per attempt), the strike accounting at the terminal failure and the bounded fresh-sandbox retry for the retryable classes ONLY. An out-of-vocabulary/malformed/secret-bearing task is a platform-layer rejection BEFORE any probe or dispatch effect (zero substrate contact).
- **The journal rides the platform's OWN step-event vocabulary** (the `executions` EventEnvelope ledger): `sandbox-admitted` (the fresh-sandbox admission, spec digest), `sandbox-denied` (the pre-effect refusals — readiness, quarantine, unwired), `sandbox-completed` (the settled observation — outcome class, the failure facts as digests/facts, never payload bytes) and `agent-action-recorded` (the per-attempt journal, exactly once per attempt; also the quarantine-engagement event with the strike/threshold/window facts).
- **The mechanical criteria** (`deriveSubstrateFailureCriteria`, PURE, fully pinned by the per-submission oracle — never re-derived from the observed run): substrate-class, attribution-layer, retry-classification (every failed attempt carries the injected class/retryability — a misattributed attempt FAILs), attempt-count, bounded-retry (no infinite loops; non-retryable and quarantine-refused attempts are always terminal), fresh-sandbox-per-attempt (distinct + canonical identities), readiness-gated-dispatch (every dispatched attempt was probed ready in the SAME attempt; refusals never dispatch; gate refusals never probe), quarantine-contract (a gated submission never contacts the substrate — the bypass a synthetic sequence produces FAILs mechanically; an engaging submission crosses at its terminal failure; the strike propagation facts match the oracle's declared before/after counts), recovery-outcome-sequence, journal-exactly-once-per-attempt, outcome-contract and economics-measured (measured usage/latency; spec/output DIGESTS only).

- **The misattributed-OOM classification deliberately overrides the adapter's label (recorded design decision).** A `timeout` token with OOM facts (exit 137 / OOMKilled, deadline not elapsed) classifies `resource-exhausted`, and a `sandbox-execution` exit 137 with OOMKilled does too: the substrate's own facts win over the adapter's guess. The REAL process runtime cannot distinguish a kernel OOM kill from other signal kills (its observation carries only `exitCode: -1` for signal deaths) — the container-family shape (137 + OOMKilled) is the evidence-rich one, so the classifier treats the kill-signal exit as the conservative OOM attribution. Trade-off: a task deliberately exiting 137 without an OOM verdict would be attributed to the substrate — acceptable (a task choosing the OOM-kill exit code is pathological), recorded here for the Lead's review.

This matches the warm-pool/capacity semantics (repeat failed submissions → the pool is bad) and keeps the multi-attempt rows (persistent loss/timeout: 3 attempts each) from spuriously engaging the quarantine mid-run. Recorded for the Lead's review; a per-attempt strike policy would be a one-function change with re-pinned oracles.
- **The REAL timeout binding derives the `deadlineElapsed` fact from the provider's own semantics (documented, never fabricated).** The crown's process-substrate binding sets `deadlineElapsed: true` on observations the REAL provider already classified `timeout` — the provider reports that token only when its own timer fired (SIGKILL on expiry), so the fact is a faithful derivation, not an invented one. A future provider that guesses timeouts without a timer would need the genuine deadline fact in its observation.
