## Architecture note (within the work order's allowed surfaces)

The work order allowed ONLY the app surface (`benchmarks/validation/apps/economic-audit/**`) plus validation tests plus this document. The audit engine lives app-locally in `driver.ts`, importing the sibling economics apps' public exports READ-ONLY (the app-owned pattern; the public SDK boundary — no `src/**` import). Two arms:

**The REPRODUCIBILITY arm** — replay the recorded economic evidence end-to-end: re-derive every adjusted-cost / attribution / substrate / cross-workload verdict from the recorded inputs (digest-verified) and prove bit-stable recomputation. PURE oracles (each a mechanical check that can FAIL with the offending items NAMED): replay bit-stability (a verdict that flips on replay FAILs with BOTH verdicts named; honest divergence records with cause are permitted where declared — the declared-divergence row), rubber-stamp detection (an audit row that verifies WITHOUT re-derivation FAILs — the re-derivation must actually execute, its trace inspected), favorable-subset sampling (an audit that samples only favorable rows FAILs with every omitted row NAMED), verdict-grounding (every audit verdict cites its evidence digest — an ungrounded verdict, a digest disagreement and an unresolvable reference each FAIL named), bounds-held (a sampled re-run's measured economics checked against the RECORDED declared bounds — an out-of-bounds value claimed held FAILs with the offending value AND the violated bound both named).

**The ANTI-GAMING arm** — re-probe every gaming vector against the FINAL integrated machinery: the ten vectors (quality inflation, latency omission, failure hiding, estimate conflation, post-hoc exclusion, window cherry-picking, regime normalization, hidden weights, silent drops, re-measurement masquerade) each probed AND caught with the mechanism NAMED, PLUS cross-vector combinations (a row that passes each probe in isolation but games the combination FAILs with BOTH mechanisms named — the missing-probe and not-caught discriminations each probed). Resolution honesty: a gaming-detected finding reported as resolved without a fix or an accepted-risk record FAILs named (the unresolved-finding discrimination); the accepted-risk shape is the honest resolution record.

**The mechanical audit-verdict vocabulary:** REPRODUCIBLE-VERIFIED / BOUNDS-HELD / GAMING-DETECTED (with the exact mechanism NAMED) / NOT-AUDITABLE (the honest boundary, with reason NAMED). The completeness oracle NAMES its violations in evidence (the house pattern — vector-not-probed / vector-not-caught / mechanism-not-named / combination-not-probed / combination-not-caught / combination-mechanism-not-named, each with the offending items named). Digest discipline: FNV-1a digests, payload bytes never recorded.

The app declares the corpus (AC1): 28 offline rows + 1 env-gated live row. The corpus includes the seven honest replay rows (re-deriving the RECORDED verdicts of VAL-041..048 from their digest-referenced recorded inputs, bit-stable), the declared-divergence row, the two NOT-AUDITABLE boundary rows (live-measured slices; payload-bytes discipline), the offline bounds row (BOUNDS-HELD over the recorded confidence), the ten canonical vector probes (each GAMING-DETECTED with the mechanism named), the three cross-vector combination probes, the accepted-risk finding row, the four adversarial audit-probe rows (rubber-stamp / favorable-subset / off-bounds / unresolved-finding — each expected to FAIL its NAMED criterion) and the live re-run row (env-gated on `OPENROUTER_API_KEY`, honest NOT RUN).
