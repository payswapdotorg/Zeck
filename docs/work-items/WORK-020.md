## The learned planning-policy model (design decisions)

- **Advisory evidence, never authority (§10)**: the artifact's `policyClass` is the frozen `non-authoritative-learned-planning-policy` marker; the learned-policy service's deps are the non-authority quartet (store, digest, generateId, clock) — no policy, capability, budget or execution seam anywhere in the lifecycle; the learning module never imports planning/policies internals (the planning-owned port/adapter is the only seam).
- **Structural non-authority, twice**: learning output cannot EXPRESS restrictions (closed artifact shape: preferences only — no ceilings, no allow/deny lists), and the policies-owned vocabulary scan makes them UNDELIVERABLE at the consumer seam (`POLICY_DENIED` on any restriction leaf/dimension key, walk-depth-bounded, fail-closed on non-walkable values).
- **One planner, one state machine**: the consultation is an optional read inside the EXISTING `createPlannerService` flow, positioned after the admissibility filter and before `selectStrategy`; `selectStrategy` gained an optional ordering key that refines ONLY the cheap-first cascade — the deterministic-first branch (ADR-0007) is untouched, admissibility/sufficiency/quality inputs are untouched, and an un-wired seam is byte-identical to the baseline.
- **The governed-selection audit anchor**: the planner computes the learning-free `governedSelection` first; the consultation capture records the learned preference, `rejectedByPolicy`/`unmatchedSubjects`, agreement, and the honest `appliedToSelection` verdict (true only when a promoted ordering refined the live selection away from the governed default). The capture is part of the closed decision-record shape (`validatePlanningDecision` validates it).
- **Honest confidence or absence**: ranked subjects require population ≥ the frozen floor (5); uncertainty is classified from binomial spread and preserved (never collapsed); below-floor subjects and classes without qualifying evidence produce NO preference — uncertainty never becomes executable guidance.
- **Publication is the only deployment act**: generation/evaluation write learning-owned observational rows; ONLY `publishLearnedPolicy`/`rollbackLearnedPolicy` append to the journal; the active pointer is the LATEST entry (derived, never duplicated); shadow mode is deliberately NOT a publication mode (it is pre-publication evaluation).
- **Rollback is publication, never rewrite**: rolling back appends a `rollback` journal entry of the prior version's most recent publication (mode + evidence reused verbatim); the artifact's rollback metadata names the strictly-earlier version + digest, so the target is deterministic; history stays byte-identical (physical immutability triggers on all three tables).
- **Idempotency/convergence everywhere**: generation replays on the same population fingerprint; version races converge via `UNIQUE (application, policy_version)` + winner re-read; evaluation and publication identities are content-derived (retries converge); concurrent distinct publications serialize through `publication_seq` with one active pointer.
- **Migration discipline (parallel wave)**: **WORK-020 claims 0017** — `0017_learned_planning_policies.sql` (three learning-schema tables: `learned_planning_policies`, `learned_policy_evaluations`, `learned_policy_publication_log`), pinned in the file header; 0015 untouched (burned), 0016 untouched (WORK-022), 0018 left to WORK-024. Tenant scope is never dropped: every table carries `(application_id, tenant_id)` FK to `applications.applications`; evaluations/publications FK to their own application's policy version (composite FK).
- **Two refreshed directly-required gates** (stale after the governed-selection split and the new tables): the M8 mutant target in `tests/discrimination/learning-nonauthority.discrimination.test.ts` now mutates before the `governedSelection` call; `tests/integration/postgres/learning-schema.test.ts` inventories the three 0017 tables (14 learning tables total). No other gate needed changes.

## Limitations

- **The learned ordering refines, never admits**: a published learned policy can only re-order the already-admissible, quality-satisfying cascade pool and can never touch the deterministic-first branch, sufficiency or admissibility — this is the design (the boundary IS the feature); a customer wanting the learned preference to override the cost-first default must tighten the POLICY (the authority path), not the learning output.
- **The v1 mining algorithm is a frozen disclosed ruleset** (`LEARNED_POLICY_ANALYSIS_VERSION = 1`): success-rate-descending ranking with cost/latency tie-breaks, population floor 5, binomial-spread uncertainty classes; the version is recorded on every artifact and pinned at the consumer seam. Richer models (contextual features, regret minimization) are future analysis versions — each is a new version of the same honest-evidence contract.
- **Canary mode is recorded divergence evidence, not live traffic splitting**: the planner records what a canary publication WOULD prefer against the governed selection (the honest `appliesToSelection=false` capture); there is no per-request traffic-percentage runtime in v1. Real shadow traffic comparison beyond the scorecard-basis evaluation is future experience-layer work.
- **Evaluation compares against the cost-first baseline implied by the same scorecard** (the governed default ordering), not against an independently-configured baseline policy; the basis (exact scorecard id/version) is recorded on every evaluation.
- **No API/operator surface for the lifecycle is wired**: the service + stores are module-level public contracts (the same stage WORK-014/017/022 shipped at); an HTTP route/composition-root wiring is future experience-layer work. The planner seam is wired only in tests today — no production consumer consults learned policies yet, so the ordering influence is proven, not exercised in production.
- **The restriction-vocabulary boundary is a key-name scan over the closed JSON universe** (bounded depth, fail-closed on non-walkable values): it mechanically rejects restriction leaves and dimension containers; a semantically-equivalent restriction expressed under an arbitrary alias key is caught by the closed artifact shape (the learning module structurally produces only preference fields) — the two layers are defense in depth, disclosed.
- **CI runs no real-PG suites** (the standing WORK-002 convention): the PG proofs are local-verified against real PostgreSQL 16.4 and recorded above; the GitHub `Repository Governance` workflow covers governance/typecheck/lint/architecture/unit/integration (PG-skipped by design).
- **The known baseline quirks are recorded, not fixed**: the frontier-state `parallelWave.baseRevision` value and the WORK-019 tree absence are Architect-owned reconciliation items (disclosed in Pickup state above).
