## The crash-safety standard (the architect's review bar — the ENTIRE Work Order)

Every side-effecting operation of the long-running surface (checkpoint commit, pause, resume, lease acquire/renew/release, interruption, termination, wake-up scheduling/application) flows through the DURABLE, RECOVERABLE OPERATION STATE (`executions.execution_operations`: PENDING → COMPLETED|FAILED, stable execution-scoped keys, monotonic attempts, stage checkpoints, terminal immutability — the WORK-024 `realtime_operations` standard) and every ledger write carries its own stable idempotency key. A crash at any boundary leaves the honest PENDING row; the retry resumes from the recorded stage with EXACTLY ONE durable side effect per stable key. The committed-effect distinction is explicit: the checkpoint digest probe (`findCheckpointByDigest`) proves an already-committed external effect and converges onto it WITHOUT the lease guard and without a second row; an uncommitted effect is lease-guarded (P14 vs P2 — the two faces of the same rule).

## Design decisions (the composition with the FROZEN lifecycle)

- **The frozen lifecycle is untouched and is the ONLY status write path**: `domain/state-machine.ts`, `domain/execution.ts`, `application/execution-service.ts` and `adapters/sql-execution-store.ts` are byte-identical to the base; the only change under `domain/` is the ADDITIVE step-event vocabulary of `domain/event.ts` (six observation commands: `checkpoint-recorded`, `interruption-requested`, `wake-up-scheduled`, `wake-up-applied`, `resume-recorded`, `resume-denied`) — the WORK-010/011/013/012/032 additive discipline. Pause moves status ONLY through the frozen `wait-tool`/`wait-user`; human interruption ONLY through `wait-human`; resume ONLY through `resume`; governed termination ONLY through `cancel` (LG3 gates the exact command set; LG4 freezes the vocabulary).
- **One provenance authority**: all checkpoint/lease/wake-up/interruption/resume evidence rides the CANONICAL EventEnvelope ledger through the executions public `recordStepEvent` seam; migration 0022 stores durable state, NEVER a second event stream (LG6), and never writes execution status.
- **The lease is an EXTENSION table keyed by the existing execution identity**: one row per execution (PK), monotonic epochs (re-acquisition = epoch + 1 — a stale (owner, epoch) pair can never match again), heartbeats as counting side effects with monotonic heartbeat_count, one-way release with an auditable cause vocabulary, physical guards on every transition. Lease conflicts fail closed; human authority (interruption/termination) force-releases any live lease, never silently.
- **The committed-effect distinction**: the checkpoint content digest is the external-effect identity. The probe runs BEFORE the lease guard — a checkpoint row with the same digest for the same execution PROVES the side effect committed (the crash window between insert and stage write) and converges without a second row; the convergence-aware physical gate lets the exact duplicate through the UNIQUE arbiter while a different digest on the same sequence fails closed as key reuse.
- **The materiality rule is explicit and pinned**: `MATERIAL_CHANGE_DIMENSIONS` = {planRevision, resourceClass, environmentId, environmentSpecDigest, requiredCapabilities, maxCostMicroUsd}. Changed → re-enter the CURRENT policy admission (the authorize-seam dimensions), the sandbox resource axis (for resource dimensions) and the budget reservation (for the cost bound); denial → journaled + durably FAILED (typed replay, never re-derived — the pre-crash authority state is never trusted, only the live engine: P5). Unchanged → zero authority consultations (the honest no-re-admission record).
- **The stable key scheme (execution-scoped)**: `longRunningOperationKey(kind, "<executionId>:<idempotencyKey>")` — every operation key carries the execution identity (C23: the same caller key on two executions is two independent claims). Ledger evidence keys are per-subject stable (`checkpoint:<executionId>:<sequence>`, `<operationKey>:requested`, `wakeup:<executionId>:<wakeKey>`, `wakeup-applied:<executionId>:<wakeKey>`, `<operationKey>:denied`, `<operationKey>:resume`, `<operationKey>:recovery`) — deterministic payloads so a crash-recovery re-write under the same key converges.
- **Wake-ups are deterministic and idempotent**: `(earliestWakeAt, id)` due ordering over the scheduled partial index, the write-once status machine `scheduled → applied | superseded`, the `claimed` stage before any side effect, the recovery scan for PENDING claims, and the materiality-free wake-driven resume under the checkpointed facts.
- **agents/sandbox seams**: `src/modules/sandbox/` was used for exactly one directly-required seam — `createExecutionResumeReadmission` (the resource re-admission over the REAL WORK-012 environment catalog + policy admission chain), exported through the sandbox public barrel. **`src/modules/agents/` was NOT used** — no agent-fabric resume seam was required by the protocol; recorded as honestly unused (the WORK-024/025 precedent).
- **Migration discipline (parallel wave-4)**: **WORK-028 claims 0022** — `0022_long_running_execution_state.sql` (four executions-schema tables: `execution_checkpoints`, `execution_leases`, `execution_wakeups`, `execution_operations`), pinned in the file header AND here; 0015 untouched (burned — WORK-019), 0016–0020 untouched (merged siblings), 0021 left to the sibling WORK-026. Tenant scope is never dropped (composite `(application_id, tenant_id)` FKs).

## Limitations

- **No real multi-process worker fleet is exercised**: the crash model is the in-repo standard — a Proxy-injected process death at a durable boundary with a re-booted service over the SURVIVING world (real PG, real seam engines). True OS-level kill -9 of separate worker processes with independent clocks is not exercised; the unit world's clock is fake-controllable, the PG proofs use wall-clock leases (the timing-sensitive P2/P14 use ~100x-margin TTLs and are stable across repeated runs).
- **No background wake-up scheduler/daemon runs**: `applyWakeUps` is a deterministic scan + apply operation proven idempotent and convergent; a production timer/scheduler loop that invokes it is experience-layer work outside this Work Order's declared surfaces.
- **Lease TTL/heartbeat policy is caller-supplied**: the service enforces the lease discipline; the choice of TTL/renew cadence per workload is deployment policy, not encoded here.
- **`workerTransition` delegates to the frozen transition surface after the lease guard** — it is the seam future worker runtimes will use; no production worker runtime consumes it yet in-tree (the agents seam went unused, recorded above).
- **The budget reservation on a materially changed cost bound is reserved, not settled** against actual usage at resume time — usage settlement is the budgets module's own lifecycle (WORK-004 authority); the reservation id is carried in the operation stage for that reconciliation.
