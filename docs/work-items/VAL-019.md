## Issue findings and protocol

- **`replaceAll` with a non-global regex throws at run time (found by this slice's own unit tests, fixed pre-commit).** The first draft of the workspace path normalizer called `String.prototype.replaceAll(/\/+$/, "")` — a non-global regex argument, which throws `TypeError` at run time (typecheck does not catch it). Classification: fixture-design defect. Solution: segment-based path normalization (no trailing-slash regex at all). Verification: the domains unit suite's boundary tests. Impact: none (found before any dispatch path ran).
- **Research retrieval ordering instability (found by this slice's own unit tests, fixed pre-commit).** The first keyword scoring let SRC-5 outscore SRC-4 on the returns query, so the natural read order contradicted the pinned expected trace order (a REAL-run flakiness source). Classification: fixture-design defect. Solution: keyword-set tuning + the stable source-id tiebreak so the deterministic retrieval order matches the natural reading order ([SRC-4, SRC-5]). Verification: the domains unit suite's retrieval-determinism test.
- **Exact-argument traces vs redundant model calls (calibration decision).** The VAL-012 precedent compares tool traces exactly; free-form agents (REAL runs) interleave redundant reads. Solution: all VAL-019 rows use the in-order subsequence comparison (the val-012 workflow-row semantics — redundant calls are inefficiency evidence, not routing failures) with per-step exactness checked on the MATCHED entries only. Impact: robustness of the Lead's live re-run without weakening the oracle.
- **Expected-failure rows complete honestly through multiple paths (by design).** The three expected-FAILED edge rows (fake instrument, outside-root read, impossible spec) can fail either by attempting (tool-rejection/failed tests) or by refusing (honest refusal + goal-achieved FAIL) — both land FAILED mechanically; neither can fabricate a success. The forged-approval row fails specifically through `hitl-gate-timeout` (no recorded decision), which is the AC4 unauthorized-effect semantics.
- **No live provider verification was possible in this sandbox** (no credentials, by design). The rail binding (structured-output agent protocol, usage/cost capture, retry taxonomy) mirrors the VAL-012 crown precedent exactly; the Lead's credentialed re-run is the live verification. Any live divergence is an honest finding to record here.
- **Model-capability risk on gated-tool invocation (recorded risk).** The operations rows require the model to actually INVOKE the approval-gated tools (the system prompt instructs this explicitly); a model that refuses to invoke gated tools without human contact would fail the healthy rows honestly. The default rail model followed the equivalent VAL-012 protocol; if the Lead's re-run observes refusal behavior, the finding is a capability-matrix datum, not a harness defect.
