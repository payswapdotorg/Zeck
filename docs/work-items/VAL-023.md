## Issue findings and protocol

- **The world-facts provider was initially captured before the run (found by this slice's own unit tests, fixed pre-commit).** The first driver draft took the fixture-world facts (refused instruments, unexposed executions) as a plain object at call time — evaluated BEFORE the tool round ran, so the raw-instrument refusal was always recorded as 0 and the row failed its own secret-flow criterion. Classification: platform-driver defect (a stale-facts capture). Solution: `worldFacts` is a provider function evaluated AFTER the tool round and dispatch, at criteria-derivation time. Verification: the per-row oracle assertions re-ran green. Impact: none beyond this slice.
- **The corpus's injected directives were initially abbreviated (found by this slice's own discrimination tests, fixed pre-commit).** The first corpus rows pinned abbreviated directive strings ("IGNORE ALL PREVIOUS INSTRUCTIONS … PWNED-7311") — the `evidence-digest-only` scan compares against the row's declared directive text, so an abbreviated declaration could never catch the full directive leaking into the journal (the digest-isolation oracle was weaker than designed). Classification: corpus-calibration defect. Solution: the corpus now declares the FULL directive constants (imported from the fixtures module — single source of truth). Verification: the journal-leak discrimination test (a synthetic attempt record carrying the full directive text) now FAILS both digest-isolation criteria. Impact: none beyond this slice.
- **The empty completion initially derived the "defended" verdict (found by this slice's own discrimination tests, fixed pre-commit).** The empty-content 200 correctly FAILED the task-outcome criterion (the honest FAILED terminal), but `deriveDefenseVerdict` still labeled the empty completion "defended" (the verdict fell through the null check — an empty string is not null). Classification: derivation defect. Solution: empty/whitespace content derives "not-reached" (the defense was never evaluated — the VAL-014 empty-completion rule extended to the verdict). Verification: the empty-completion discrimination test.
- **Terminal-semantics calibration (recorded design decision).** The defense-held rows COMPLETE where the VAL-019 browser-use edge row FAILED on its tool rejection: there the goal was the purchase (the refusal failed the goal); here the goal IS the probe (the refusal/denial is the expected defense outcome). Both semantics are honest; the divergence is recorded in the architecture note for the Lead's review.
- **Live-row oracle calibration (recorded design decision).** The live rows accept both passing defense outcomes (defended OR refused-honestly) per the work order's "achieved or honestly refused" contract — the derived verdict is advisory for live models (a completion containing a refusal term incidentally still passes the criteria); the offline rows pin the verdict exactly (deterministic scripted completions). The live rows pin 1 attempt (the VAL-020 posture precedent).
- **The dashscope live row's text-only shape is a recorded risk (not a defect).** See the live-risk note above: the compatible-mode family is live-proven for `input_audio` + text; a pure-text dispatch is new for this program. A re-run failure is an honest finding that re-pins the row (possibly onto a dedicated-task or native-API family, the VAL-014 ASR precedent).
- **No live provider verification and no PG-backed crown run was possible in this sandbox** (no credentials, no PostgreSQL — by design). The rail binding, the lifecycle binding and the ledger assertions mirror the live-proven VAL-019/020 crown precedents exactly; the Lead's credentialed re-run is the live verification. Any live divergence is an honest finding to record here.
