## The advisory model (design decisions)

- **Analysis is an Execution, enforced by composition**: the learning module stays a pure observation island (the analyzer's deps are exactly {store, digest, generateId, now} — the WORK-014 non-authority quartet, pinned by architecture gates and static mutants). Tenant/policy/capability/budget/sandbox governance lives in the API route, which drives a REAL execution through the executions authority's public contract (create → authorize → plan → queue → start → verify → pass, the analysis digest bound as the verification result) BEFORE and AFTER the analyzer runs. A policy denial fails closed with zero learning rows written.
- **The selection is caller-supplied read-only data**: the analyzer never reads repositories, never fetches code, never executes customer code — the customer submits the selected subgraph with its observed evidence axes. Provenance (repository/revision/file/symbol) is mandatory per node and revision-mismatched (stale/mixed) selections are rejected, never normalized (M28). The v1 bound is ≤256 nodes, fail-closed, disclosed.
- **Detection is pure and deterministic over OBSERVED evidence**: same graph → same findings. The nine opportunity classes fire on the observation axes (input variability, semantic complexity, error rate, verification counts, distinct input/output counts, constant output, population, topology). Cost alone NEVER justifies a recommendation (the §19 RED discipline): when the axes say the work is genuinely semantic, no removal/replacement finding exists.
- **The candidate/verified split is physical, not stylistic**: 'verified-equivalent' is not an insertable equivalence potential (closed vocabulary + SQL CHECK); verified is reachable ONLY through the evidence-gated transition (differential comparison, PASS status, same-revision binding, comparable populations, comparison population ≥ finding population, confidence ≥ medium). Ratings are preference-only evidence that can reach 'candidate' and nothing beyond.
- **VOI is a disclosed deterministic function, doubled physically**: the emission rule is pure (gain table + strict threshold + materiality + maxPrompts), and migration 0016 makes a friction-unjustified prompt UNINSERTABLE (`prompts_voi_gate CHECK (gain > threshold)`).
- **Idempotency follows the house patterns**: the analysis durable identity is the analysis EXECUTION (UNIQUE execution_id — retries converge; a different analysis basis on the same execution fails `IDEMPOTENCY_KEY_REUSED`); rating identity is (finding, rater, question) — duplicates converge, conflicts fail closed; the transition id is content-derived (the WORK-017 activation-journal pattern) so the same logical transition retries to the same journal row.
- **The planner seam is planning-owned and consult-only** (the WORK-007/009/014/017 consumer-owned-port precedent): planning defines the port + domain mirror + validation; the ADAPTER (values, in planning/adapters) maps the learning public `OpportunitySignalSource`; planning domain/application/ports consult learning TYPE-ONLY (architecture-gated). The consultation happens AFTER the governed selection and is captured as decision evidence — the implied preference (fewest/most generative steps among ADMISSIBLE candidates) is recorded, never applied.
- **Declared-surface honesty**: the implementation modifies learning, planning, api (+ shared wire/serialization + directly-required tests/evidence). The `context` and `verification` declared surfaces are consumed CONCEPTUALLY, not modified: context-enhancement and verification-enhancement are opportunity CLASSES emitted by the analyzer (recommendations FOR those modules, not changes to them), and the verified-equivalence evidence contract deliberately MIRRORS the verification comparison shape (PASS/FAIL/INCONCLUSIVE + comparable populations) without importing the verification module — preserving the learning observation island. Disclosed under Limitations.
- **Wire surface is allowlist-constructed**: the report/finding/prompt/rating/transition serializers name every field explicitly (the secret-safety discipline); the route inventory gains exactly four routes; no patch/diff/deploy/promote surface exists (asserted by the public-surface gate's forbidden-route list).

## Limitations

- **The v1 analyzer is observation-driven, not code-parsing**: it analyzes the caller-subplied selected subgraph with its observed evidence axes; there is no repository crawler, AST parser, or automatic trace miner. Enriching evidence axes (and deriving them from execution telemetry automatically) is future work — the domain vocabulary (NodeObservation) is the extension point.
- **`context` and `verification` declared surfaces are NOT modified**: context-enhancement/verification-enhancement are opportunity CLASSES emitted for the customer (recommendations FOR those modules); the verified-equivalence evidence contract mirrors the verification comparison shape without importing the verification module (preserving the learning observation island). No new verification evaluator or context pipeline was built — out of the minimal coherent scope.
- **§10 user execution testing is composition-proven, not benchmark-proven**: any analysis runs through the executions authority's admission chain (proven by composition, architecture ordering gates and the denial red records); a full "controlled execution of a selected function inside the sandbox with evidence replay" product flow (WORK-019's fleet) is future integration — the analyzer never executes customer code by construction.
- **The VOI gain table is a disclosed heuristic constant table, not measured utilities**: the emission decision is deterministic and the basis is recorded, but the gain numbers (0.9/0.6/0.25/0.05) are design constants, tunable per request through the friction configuration.
- **Confidence is population- and observation-shaped**: the thresholds (30/10/3, error-rate 0.2/0.3, cacheable ratio 0.25) are frozen disclosed constants of the v1 ruleset (`OPPORTUNITY_ANALYSIS_VERSION = 1`); the ruleset version is recorded on every analysis and the domain mirror pins it at the planner seam.
- **The planner records an implied preference but never applies it** (by design): a future work item may surface the consultation in the plan explanation output; today the durable decision record carries the evidence and the selection rationale stays governed.
- **CI runs no real-PG suites** (the standing convention): the PG proofs are local-verified against real PostgreSQL 16.4 and recorded above.
- **The rating counterpart pair is recorded but not cross-validated against a second real finding** (beyond null/self checks): pair ratings on two distinct findings are representable and validated for scope; the pair-differential flow is exercised through the single-finding path in v1.
