## The runner-fleet model (design decisions)

- **Runners are a SUBSTRATE, not an authority** (the critical architecture rule): the fleet owns assignment BOOKKEEPING only. `RunnerFleetDeps` is pinned to exactly `{store, sandboxStore, generateId, now, heartbeatWindowMs, leaseDurationMs, hashToken}` — no policy/budget/capability/verification/executions seam exists (proven by the RD7/M7 deps-shape mutant). The assignment vocabulary is physically disjoint from every execution status (RD15 mutant); no execution status, creation or transition surface exists anywhere in the fleet or the integration (RD9/M9/M13 mutants + the boundary gate's import scan).
- **Registration is not trust**: a registered runner is `untrusted` and serves NOTHING until the explicit operator grant (`authorized`); revocation is terminal-immutable (a replacement is a NEW registration — the physical triggers make re-authorization unrepresentable). Registration identity is WRITE-ONCE and content-addressed by the `runnerRegistrationFingerprint` (the identity core: environment, version, capabilities, token fingerprint): duplicate registration converges, a different core conflicts.
- **External identity is not authorization**: the registration token is stored ONLY as its SHA-256 fingerprint; at reconnect the presented token's fingerprint must match — it proves channel continuity, never grants anything. Raw-secret-shaped tokens are rejected at validation (M17).
- **Health is observed, not claimed**: assignment eligibility requires explicit `healthy` AND a heartbeat inside the freshness window; the SQL insert evaluates `authorization_status = 'authorized' AND health_status = 'healthy' AND last_heartbeat_at >= $cutoff` IN THE SAME STATEMENT as the insert (M20: a dead runner is physically unassignable even under a race between the service pre-checks and the insert).
- **One active assignment per runner**: the partial unique index `runner_assignments_active_slot ON (runner_id) WHERE status IN ('assigned','dispatched')` makes split-brain ownership unrepresentable (M19); release/expiry free the slot exactly once.
- **Idempotency rides the house pattern**: the assignment row keyed by `(application_id, assignment_key)` IS the durable outcome — same key + same request fingerprint replays the committed row; same key + different fingerprint fails `IDEMPOTENCY_KEY_REUSED`; concurrent duplicates converge through unique-index arbitration (`ON CONFLICT DO NOTHING` + re-read). The provider derives its key from the PARENT sandbox identity (`runner-assign:<sandboxId>`): a retry of one logical dispatch replays the SAME assignment and the SAME handoff (the one-shot nonce).
- **The lease is the reconciliation bound**: dispatch and reports are lease-bounded (late ones fail closed with `EXPIRED`); expiry is terminal (a crash between dispatch and report leaves the honest `dispatched` row; expiry terminalizes it — never silent re-execution); a late report is refused because convergence cannot be proven.
- **The handoff is sanitized by construction**: task argv + explicit public env, limits, network allowlist, opaque filesystem refs, secret REFERENCES — no value field exists anywhere in the runner contracts; host-shaped references are refused at validation. The report is the sandbox-axis observation ONLY (the runner can never express verification/provider/tool outcomes).
- **Provider neutrality (M14)**: the microVM/VM tiers are named by isolation CLASS only; `IsolatedImageRuntime` is the seam; without a runtime client the tiers fail closed (`runtime-unavailable`) — no Firecracker/QEMU/KVM/cloud vocabulary exists anywhere under `src/` (the vendor-vocabulary scanner over every runner contract + the public barrels).
- **The integration delegates everything**: `src/integrations/runners/` validates untrusted external submissions (fail-closed) and delegates to the sandbox module's PUBLIC `RunnerFleetService` (the one fleet authority); its `CustomerRunnerChannel` implements the sandbox port `RunnerChannel` and routes to `CustomerRunnerEndpoint`s (the external twin; the in-memory endpoint is the composition/test fake). No registry, no authority logic, no execution surface (RD16c/M16c mutant).
- **Sandbox-surface change (declared surface)**: `IMPLEMENTED_SANDBOX_KINDS` extended with `microvm`/`vm`/`customer-runner` (the vocabulary already existed in the frozen kinds list; these now ship providers). Directly-required test updates: the migration-inventory gate (composition-boundary) asserts 0015; the integrations-boundary gate admits the runners→sandbox-public-barrel import (the payment-rails/substrate-federation precedent); module-skeleton/composition inventory tests cover the new integration layout.

## Limitations

- **No concrete microVM/VM runtime client ships**: the dedicated-kernel tiers are the provider-neutral contract + fail-closed adapters (`runtime-unavailable` without a client — the honest v1 posture; vendor runtimes arrive with the owning future Work Orders, behind the `IsolatedImageRuntime` seam). This is the deliberate M14 boundary, not a gap in ENV-003: the evolution path is the shipped, tested, fail-closed contract.
- **No real network transport for the customer-runner channel**: the integration ships the channel/endpoint contracts and the in-memory simulated runner; a real transport adapter (an operator-facing gateway route) is future experience-layer/integration work — the tests prove the governed lifecycle over the real SQL fabric and the real channel seam.
- **Runner selection is deterministic-first-registered** (`selectEligibleRunner`): eligibility filtering (authorized, healthy, capability-matching, free) + earliest-registered tiebreak. Scheduling intelligence (load-aware, cost-aware, affinity) is deliberately out of scope — the substrate does not become a planner.
- **The fleet has no background sweeper**: lease expiry is an explicit, idempotent operator/reconciliation call (`expireAssignment`), not a cron. A production control loop belongs to the future operations surface; the fail-closed semantics (late reports refused, terminal expiry) are proven.
- **Heartbeat observation is operator/platform-driven**: the freshness window arbitrates assignment; the platform-side probe scheduling (per-endpoint health checking) is composition work not shipped here.
- **The gateway's idempotency keys are slug/runner-derived constants** (`runner-register:<slug>`, `runner-authorize:<runnerId>`): the fleet's durable identity convergence makes the keys advisory (registration is keyed by (application, slug); authorization is state-based and idempotent) — consistent with the house pattern where the durable row is the outcome.
- **CI runs no real-PG suites** (the standing WORK-002 flag); the PG proofs are local-verified against real PostgreSQL 16.4 and recorded above.
- **The PG suite can hit the documented pre-existing teardown transient** under heavy parallel load (late unhandled socket error in `executions-concurrency.test.ts` AFTER all tests pass — cleanup accounting only; the WORK-018 evidence documents the identical transient). The lease-expiry PG tests use deadline-aware sleeps and 2s dispatch margins so expiry semantics stay deterministic under load stalls.
