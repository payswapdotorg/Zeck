## The architect's crash-safety correction (PR #46 review cycle)

PR #46 was blocked in review on a **crash-safety defect**: operation state was not durable/recoverable and rail-level idempotency keys were not stable across process deaths. The branch was restored to the original implementation head `07b12d564a45f8c8a5c93a376df6926a249cf05d` (review noise removed) and this increment implements the required correction:

- **Durable, recoverable operation state**: every governed operation that can perform an external side effect (session-start, turn-delivery, human-transfer, session-close) owns ONE row in the new `deployments.realtime_operations` ledger with a `PENDING → COMPLETED | FAILED` machine, a monotonic `attempts` retry ledger, and a bounded stage CHECKPOINT (`session-opened` / `responded` / `rail-issued`) that marks the point of no return. The durable claim is written BEFORE the rail side effect and the durable completion AFTER every durable outcome; a crash in between leaves the row PENDING and a retry RESUMES it (a COMPLETED row replays its outcome with no side effect; a FAILED row replays its recorded failure). Physical discipline in migration 0018: UNIQUE (application, operation_key) arbitrates the claim; the lifecycle trigger makes terminal rows immutable; attempts never regress; the identity core is write-once; rows are never deleted; the checkpoint is writable only while PENDING (bounded ≤ 4 KB, never media/secrets).
- **Stable rail-level idempotency keys**: every `RealtimeRail` method that can perform an upstream side effect (`openSession`, `deliverTurn`, `transferCall`, `closeSession`) carries an `idempotencyKey` derived deterministically from the durable coordinates (`realtimeRailOpenKey/DeliverKey/TransferKey/CloseKey`) — a retry or crash-resume re-issues the call under the SAME key and the rail converges (exactly one upstream side effect, ever, returning the original acknowledgment with `replayed: true`). The key ledger lives on the RAIL side (it models the external provider, which survives a Zeck process crash) — the in-process simulated rail implements it as its in-memory key ledger; a real provider implements it with its own idempotency-key semantics. The turn responder seam carries the session-scoped `turnKey` so a production responder can converge paid inference across crashes.
- **Recovery semantics**: resumption past a checkpoint NEVER re-runs admission or the paid-inference seam (the decision preceded the side effect; the checkpoint's facts complete the durable tail); before a checkpoint, re-running is correct and bounded by the seams' own key convergence. Terminal-status reconciliation paths complete PENDING close/transfer operations when the terminal move is itself the durable proof. Evidence payloads riding the executions idempotency are REPLAY-STABLE (identical for the original invocation and any resumer — the executions arbitration is by key + fingerprint; unstable markers would fail a legitimate recovery closed; recovery observability rides the journal causes, which are never digested).

**Defects the crash-injection proofs found and fixed during this increment** (the proofs earned their keep):

1. **Session-scoping of event-key-derived discriminators**: event keys are unique per (application, SESSION) — two concurrent calls may legitimately reuse an upstream event id — but the turn-delivery operation key, the rail deliver key, the responder turn key, the budget operation id and the executions evidence keys were application-scoped. A same-key turn on another session collided (false convergence / fail-closed). All event-derived keys now carry the session identity (`${session.id}:${eventKey}`).
2. **Replay-stability of executions evidence**: the turn/transfer/start evidence payloads carried invocation-dependent markers (`recovered`, `railReplayed`, `executionReplayed`, cause suffixes) — a crash-resume or concurrent duplicate re-recording under the same idempotency key failed CLOSED on the executions fingerprint arbitration. The payloads are now deterministic; recovery markers moved to the (never-digested) journal causes.
3. **The concurrent checkpoint race**: a concurrent duplicate of an in-flight turn could hit `recordRealtimeOperationCheckpoint` after the winner completed the operation → `INVALID_STATE_TRANSITION` rejection. The checkpoint write is now race-tolerant (re-read: terminal → the winner owns the outcome, our tail converges through the stable keys).

## The realtime session model (design decisions)

- **The channel session is the twin, never the primary**: a realtime session MAPS TO a governed Execution opened through the executions public create seam (idempotent by key); a realtime session IS a running governed run — the ledger adapter walks the public transition surface (authorize → plan → queue → start) to RUNNING before provenance rides; execution status is touched ONLY through public transition commands (`wait-human`/`resume` for human escalation). The deployments module owns none of the executions vocabulary (RT8).
- **One provenance authority**: turns/interruptions/transfers/failures/significant actions ride the executions EventEnvelope ledger as step events (executions-owned "agent-session-started" / "agent-action-recorded" / "agent-session-completed" commands, semantic detail in payload/reference); `deployments.realtime_events` is the CHANNEL journal — session state, inbound idempotency ledger and the `ledger_sequence` linkage — never a second event authority. The store's append is named `appendChannelEvent` precisely to keep the executions vocabulary exclusive.
- **Admission ordering is frozen and pre-side-effect**: TENANT (server-derived, durable-row-decided) → POLICY → CAPABILITY → BUDGET (paid routes only) → SECRET (mediated, reference-only grants) → then the responder and the rail delivery. Denials are journaled on both ledgers before the typed failure (`POLICY_DENIED` / `CAPABILITY_UNAVAILABLE` / `BUDGET_EXCEEDED` / `AUTHORIZATION_DENIED`). A failed delivery/mediation releases the reservation.
- **Idempotency everywhere, physical**: session creation converges on UNIQUE (application, idempotency_key) with creation-fingerprint arbitration (same key + different body = `IDEMPOTENCY_KEY_REUSED`); the rail channel coordinate is UNIQUE (application, channel_ref, epoch); inbound events converge on UNIQUE (application, session, event_key) with body-digest arbitration (a poisoned replay fails closed); guarded single-row mutations arbitrate concurrent status moves (first writer wins, replays converge on the committed row).
- **The stale-callback guard, twice**: an inbound event whose (channel_session_ref, channel_epoch) does not match the session's CURRENT coordinates is rejected by the service AND physically by the migration's `rt_events_channel_fresh_guard` trigger (a reattach permanently supersedes the old coordinates — the epoch is monotonic and the old pair can never match again).
- **Reconnect never re-identifies**: `reattachSession` binds a new channel coordinate at epoch+1 on the SAME session and the SAME execution identity (no execution open anywhere in the path — the S7 static mutant proves a reattach gaining an execution open is flagged); the execution identity is never rewritten (rollback/promotion move only the deployment pointer).
- **Raw media stays in the artifact plane**: events carry bounded previews (≤512) and ARTIFACT REFERENCES (≤512) only — the raw-secret nine-pattern refusal (WORK-011 discipline) rejects secret-looking free text at validation; CHECK-bounded columns make media blobs physically unrepresentable.
- **Deterministic routing defers to the planner**: the route class comes from the REAL planning module's deterministic-sufficiency evaluation (the same frozen decision the execution planner uses); deterministic turns perform no budget reservation (the responder's `reservationId` is null and its actual cost MUST report "0"); hybrid/generative turns reserve before the paid dispatch. No hidden model dispatch exists — the responder seam is composition-supplied and carries only the already-admitted coordinates.
- **Migration discipline (parallel wave)**: **WORK-024 claims 0018** — `0018_realtime_sessions.sql` (two deployments-schema tables: `deployments.realtime_sessions`, `deployments.realtime_events`), pinned in the file header; 0015 untouched (burned), 0016 untouched (WORK-022), 0017 left to WORK-020. Tenant scope is never dropped: both tables carry the `(application_id, tenant_id)` composite FK to `applications.applications`; sessions additionally FK to `deployments.deployments`; `execution_id` is a UUID reference WITHOUT FK by design (the executions module's idempotent identity is authoritative; the reference records provenance linkage only — recorded in the migration header).
- **Declared-surface honesty**: every changed file is under `src/modules/deployments/`, `src/platform/db/migrations/` (the 0018 file), `tests/` (directly-required tests) and this doc. The `src/modules/agents/` seam permission was NOT needed: sessions bind to application + deployment + Execution identity (not to agent-internal surfaces), and the responder/rail/router seams live in the deployments public barrel — no agents-module change was required (recorded so the Architect can verify the boundary).

- **No real external realtime/telephony rail**: all verified rail behavior is the simulated in-process rail (the provider status above). External behavior is UNVERIFIED, not observed.
- **The turn responder is a composition seam with no production adapter**: tests use recording fakes; a production responder over the deployed agent runtime (planning/models path) is future work outside this work order's declared surfaces. The response content is therefore proven as contract, not as generated content.
- **No HTTP/webhook API route is wired for the realtime lifecycle**: the service + stores are module-level public contracts (the WORK-014/017/020 stage); an inbound rail callback endpoint is future experience-layer work. The `RealtimeRailCallback` shape is defined at the port for that wiring.
- **Session policy (duration/concurrency ceilings) is carried, not enforced**: `maxSessionDurationMs`/`maxConcurrentSessions` ride the rail request (the plan's declared policy) but no background sweeper enforces duration expiry or a live-session concurrency ceiling — recording the bound, not silently enforcing it, is the v1 honesty.
- **Budget settle is best-effort after delivery** (`catch(() => undefined)`): the reservation is released on failure/refusal paths; a settle failure after a successful delivery is logged nowhere in v1 (the budget authority's own ledger remains authoritative) — a disclosed gap, not a silent bypass.
- **Denial journaling is best-effort** (both ledger and journal appends are `catch(() => undefined)`): a denial is always typed-failed BEFORE side effects; the durable denial record can be lost only if the append itself fails — the ordering guarantee (denial before effect) is unaffected.
- **The planner router's paid estimate defaults to 10000 micro-USD (1 cent)** when the planner profile carries no cost bound — a deliberate deterministic default (documented in the adapter), overridable via composition (`defaultPaidEstimateMicroUsd`).
- **No API for listing sessions by deployment/tenant beyond `getSession`/`listSessionEvents`** — operational listing surfaces are future experience-layer work (the migration's scope-listing index exists).
- **CI runs no real-PG suites** (the standing WORK-002 convention): the PG proofs are local-verified against real PostgreSQL 16.4 and recorded above; the GitHub `Repository Governance` workflow covers governance/typecheck/lint/architecture/unit/integration (PG-skipped by design).
