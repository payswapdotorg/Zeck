## Known limitations

- The local standby bootstrap requires filesystem read access to the primary's data directory (the manual base-backup procedure copies it) — true by construction for the drill-owned disposable topology and for the test world; a CI runner whose PostgreSQL runs in a service container cannot provide it, so the HA suite honestly skips there (the runbook documents `ZECK_HA_POSTGRES_BIN`). The operator form never bootstraps anything (the provider's standby exists already).
- The local drill's standby bootstrap does not use `pg_basebackup` (not shipped in the minimal embedded-binary distribution): the SQL-level `pg_backup_start`/`pg_backup_stop` + filesystem copy procedure is the documented manual equivalent and ran green in every executed drill (including crash-recovery-free promotion after SIGKILL).

- `queue-recovery` exits 1 at this head with the pre-existing RPO-anchor honesty breach — behavior byte-identical to the dispatch base (verified against a base worktree); not a WORK-057 regression.
