## Architecture note (within the work order's allowed surfaces)

`src/**` and `spec/**` are untouched (forbidden by this work order). The outcome-correctness platform slice lives in `benchmarks/validation/platform/outcome-correctness.ts` (an allowed surface), mirroring the VAL-019/021/022/024/025 platform-slice pattern. The slice's PURE derivations: `deriveGuardAdmission` (the budget guard's prune-then-decide decision table — an insufficient quota rejects BEFORE any effect stages), `deriveTerminalCriteriaAgreement` (the anyFail→FAILED invariant as a mechanical agreement: an honest COMPLETED (all criteria PASS) agrees; an honest FAILED (a visibly-FAILing criterion) agrees; a FABRICATED pass-with-fail (COMPLETED + a FAIL criterion) DISAGREES — unrepresentable; a fabricated fail-with-all-pass DISAGREES; a run that never settled DISAGREES), `deriveOutcomeReconciliation` (the four-leg mechanical reconciliation per row: terminal ↔ criteria ↔ journal ↔ fixture-state — every leg asserted; a journal effect the fixture never landed FAILS, a fixture effect the journal never recorded FAILS, a declared-set ≠ journal mismatch FAILs, an under-counting delta FAILs the fixture oracle, a phantom over-count FAILs, a double application FAILs, a FAILED row with a non-EMPTY delta FAILs the atomicity oracle, an unexpected terminal FAILs), plus the VAL-021 disciplines re-derived locally (effect multiplicity over/under/unexpected; journal gaplessness holes+duplicates; the FNV-1a digest discipline — deterministic, payload-free).

**The outcome honesty invariants this slice pins:** a FAILED execution's declared effects are NEVER applied (the atomicity of the verification boundary — the mid-work rollback discards staged effects and the fixture delta is pinned EMPTY); a replayed execution applies ZERO new effects (both after completion and after failure — the replay path carries `replayed=true` with identity preserved and `new=0exec/0rec/0fx`); a COMPLETED execution with a FAIL criterion is UNREPRESENTABLE (the adversarial fabrication is caught mechanically on the terminal↔criteria leg); the journal and the fixture world never disagree (both directions discriminated); economics and latency are measured, never estimated; evidence carries payload DIGESTS, never payload bytes.

The app (`benchmarks/validation/apps/outcome-correctness/`) declares the corpus (AC1): 9 offline rows + 1 env-gated live row. The effect families are the fixture-state oracle pattern proven across the crowns: workspace trees, order placements, ticket routings, citation attachments. Per row the corpus declares the expected terminal, the declared effect set (in declaration order — the staging order and the digest input), the declared budget-guard input, the declared verification expectation (the expected fixture digest) and the expected fixture-state delta — the EMPTY delta for FAILED rows pinned as a literal empty record. The app rides the public SDK boundary (`createZeckClient` — no `src/**` import), fires every row's submission through the harness's submit seam, and verifies its own contract with the PURE `verifyOutcomeAppContract`.
