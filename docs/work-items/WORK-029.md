## The governed edge standard (the architect's review bar — the ENTIRE Work Order)

Zeck is the **governance/orchestration plane, NEVER the safety-critical control loop** (the architecture invariant). The edge integration provides: provider-neutral contracts for edge/embodied execution targets (devices with OPAQUE `controllerRef`, neutral actuator channels, neutral workload/health vocabularies); **local execution envelopes** — the pre-authorized bounds (channels, per-channel magnitude and rate bounds, command window, command budget, disconnected-continuation policy) under which edge execution may continue disconnected, WITHOUT Zeck's cloud round trip in the control loop (the envelope is PROJECTED to the local controller keyed; the local controller re-enforces coverage on the actuator path — defense in depth); **sensor/command/actuation provenance against Zeck execution identity** (the canonical EventEnvelope ledger through the frozen `recordStepEvent` seam + the append-only actuation/sensor ledgers); **explicit policy/capability/human approval for governed physical side effects** (the full admission chain BEFORE any external dispatch; physical-write commands additionally require a bound, approved, unexpired human approval re-validated over the FULL binding chain at dispatch); **stale/unauthorized commands never reach the actuator path** (the staleness window and envelope coverage are checked pre-dispatch AND re-enforced by the local controller; every refusal is a DURABLE denied row + failed operation + `tool-denied` ledger event with ZERO actuator-path activity); and **deterministic, conflict-safe disconnect/reconnect reconciliation** (commanded actuations settle EXACTLY ONCE by key/digest/sequence; autonomous actuations confirm only within the pre-authorized envelope; anything outside is a durable VIOLATION that fails the device closed — no further authoritative commands are dispatched to a conflicted device).

Safety envelopes are **IMMUTABLE once admitted** (the content digest is pinned at insert; the only stored moves are an authorized SUPERSEDE — a NEW envelope admission that references and replaces it — and an authorized REVOCATION, which only tightens). Device identities are **tenant-scoped and revocable, revocation terminal** (never resurrected; a revocation fails-safe the envelope and invalidates in-flight authorized commands before they could ever dispatch). Edge adapters expose **capabilities and evidence, NOT authority** (the device's declared capability atoms are evidence resolved through the REAL WORK-005 registry; the controller port has NO authority and NO loop surface). Hard real-time stays OUTSIDE the cloud control plane (architecturally pinned — see the discrimination section).

Every side-effecting operation — device register/revoke, health report, envelope admit/revoke, command submission, approval request/decision, sensor ingest, reconciliation — flows through the DURABLE, RECOVERABLE OPERATION STATE (`edge.operations`: PENDING → COMPLETED|FAILED, stable keys, monotonic attempts, stage checkpoints, terminal immutability — the WORK-024 crash-safety standard) with stable idempotency keys on every durable row, ledger event, wallet finalization and external effect.

## Design decisions

- **The integration anatomy follows the WORK-031 substrate-federation module shape** (`src/integrations/edge/{domain,ports,application,adapters,internal,public.ts}` — the in-tree integrations surface, per the recorded path mapping): the domain is pure total functions + closed vocabularies; the ports are the ONLY contracts; the application composes the REAL authorities; the adapters delegate.
- **No second authority, no second execution state machine**: policy admission (the REAL WORK-007 engine behind `policy-edge-admission.ts`), capability admission (the REAL WORK-005 registry behind `edge-capability-gate.ts`), budget admission (the REAL WORK-004 `BudgetAuthority` — OPTIONAL at construction but costed commands fail closed when unwired), tenant scope (the frozen executions binding), provenance (the FROZEN executions module's canonical EventEnvelope ledger through `recordStepEvent` — the tools producer vocabulary; every durable row keys on execution identity; execution status is NEVER written here). The human gate manifests on the executions lifecycle ONLY through the public wait-human/resume transitions.
- **The multi-gate human-approval discipline**: an execution may hold SEVERAL live edge approvals at once; `waitHuman` is applied only when the execution is NOT already waiting (a sibling gate holds the state; a crashed request replays as a skip), and `resume` fires ONLY when the decision closed the LAST live gate — a partial resume would bypass a still-open human approval (AC-4 forbids it). This was the review fix of round 6 (`38f0d9d`) and is pinned by the D11 mutants.
- **The crash-stable command identity** (the WORK-027 stage-checkpoint discipline): the command-submit operation records its checkpointed command id BEFORE the wallet reservation, so a retry of a PENDING operation reuses the SAME identity and the keyed reservation converges instead of orphaning (P11).
- **The external-effect key families** (one external effect per stable key, across process death): `edge-external-envelope:<envelopeId>:<status>` (the device-side envelope projections), `edge-external-command-dispatch:<commandId>` (the ONE-SHOT dispatch), `edge-budget-reserve|settle|release` (keyed by the command identity), `edge-ledger:<scope>:<phase>` (the ledger evidence), plus the per-operation keys (`edge-op-<kind>:<idempotencyKey>`).
- **The durable simulated controller**: `simulated-edge-controller.ts` models the local edge/embodied substrate (the device rail with the admitted envelope projection, the actuator journal keyed exactly-once, the local fail-safe refusals, the autonomous tick within the envelope, the reconciliation report). It is the world-level DURABLE external substrate at the PG level (one instance shared by every boot — a real local controller outlives the Zeck process). Its external behavior is **UNVERIFIED** (declared in-tree; see Limitations).
- **sandbox/deployments surfaces**: `src/modules/sandbox/` was consumed through EXISTING public seams only where the ledger adapters bind (the executions module the ledger adapter rides is frozen-authority consumption); **ZERO sandbox-tree modifications** (the surface was declared in case a seam was required, and none was). **`src/modules/deployments/` was NOT modified** — no edge deployment seam was required (the envelope projection + controllerRef discipline needs no deployment-surface change; recorded as honestly unused).

## Limitations

- **The external edge/embodied controller behavior is SIMULATED — UNVERIFIED against any real edge/embodied substrate**: `simulated-edge-controller.ts` models the local controller (the envelope projection, the keyed actuator journal, the local fail-safe refusals, the autonomous tick, the reconciliation report) with keyed idempotent effects; real robotics/industrial/vehicle/medical-device controller behavior (real actuator hardware, real sensor buses, real deterministic control loops, real transport) is **UNVERIFIED**. The adapter declares this honesty in-tree (the architecture gate pins the declaration). The external-effect keys and the coverage/staleness/sequence contracts are what a real adapter must satisfy; the proofs verify the GOVERNED side (admission ordering, envelope discipline, staleness, reconciliation convergence, provenance, crash-safety), not the external substrate.
- **The simulated controller models the durable external substrate at the PG level** (one world-level instance shared by every booted process — a real local controller outlives the Zeck process). An in-process controller deployment (controller dying with the process) would surface stale-reference typed failures — a deployment-shape decision outside this Work Order's scope.
- **No real multi-process fleet is exercised**: the crash model is the in-repo standard — a Proxy-injected process death at a durable boundary with a re-booted service over the SURVIVING world (real PG, real seam engines, the shared durable controller). True OS-level kill -9 of separate worker processes with independent clocks is not exercised.
- **Device-side timing is logical, not wall-clock hard real-time**: the local loop's rate bounds are enforced over the reported journal (deterministic, report-local); wall-clock scheduling guarantees remain the local substrate's responsibility (the architecture invariant — they CANNOT be Zeck's).
- **No planner/agent integration**: the governed surface (register/admit/submit/reconcile) is exposed as the integration service + the public barrel; the experience-layer consumer that PLANS edge work is outside the declared surfaces.
- **Sensor retention is enforced at the storage boundary** (retained carries content, ephemeral is digest-only, fail-closed), not by a downstream scrubbing pipeline; secret-shaped content is refused by validation before persistence.
- **CI runs no real-PG suites** (the standing convention): the PG proofs are local-verified against real PostgreSQL 16.4 and recorded above; the GitHub `Repository Governance` workflow covers governance/typecheck/lint/architecture/unit/integration (PG-skipped by design).
