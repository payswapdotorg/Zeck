## Issue findings and protocol

- **The driver's first draft completed failure rows (found by this slice's own unit tests, fixed pre-commit).** The first draft derived the run terminal from the CRITERIA only (`anyFail → FAILED`): when a failure row's oracle matched perfectly (all criteria PASS), the honest FAILED dispatch completed as COMPLETED — a fabricated recovery. Classification: platform-driver defect (the exact partial-success shortcut the honesty invariants forbid). Solution: the terminal is now outcome-driven FIRST (a failure outcome ALWAYS fails the execution) with criteria failures on top; the `outcome-contract` criterion still compares the oracle's expected terminal against the outcome-derived one. Verification: the unit suite's per-row terminal assertions and the recovery/failure discrimination tests. Impact: none beyond this slice (found before any dispatch path ran).
- **Brace-heavy inline literals broke the first test parse (found by the unit run, fixed immediately).** A nested JSON literal in the content-extraction test miscounted closers. Classification: test-authoring defect. Solution: `JSON.parse` of the wire-shape string (also more faithful — the fixtures replay wire TEXT). Impact: none.
- **The corpus-well-formedness check over-constrained recovery rows (found by this slice's own unit tests, fixed pre-commit).** The first check required every retryable-injected row to exhaust the full budget (3 attempts); the recovery row legitimately recovers after ONE retry (2 attempts). Classification: test-oracle defect. Solution: the check now bounds retryable rows to [1, 1+max] and requires exact exhaustion only for all-failure rows. Impact: none.
- **The rail body for the multimodal-generation family initially omitted the declared size (calibration decision, fixed pre-delivery).** VAL-015's live-proven quota-producing dispatches carried `parameters.size`; the attribution probe now mirrors that exact body shape so the live quota row replays the DOCUMENTED producer as faithfully as possible. Classification: calibration decision. Verification: the unit suite's request-digest determinism tests re-ran green.
- **Live-row oracles pin provider postures, not provider behavior (recorded design decision).** The three live failure rows pin the DOCUMENTED credential postures (AllocationQuota 403 for the QWEN imagegen family; AccessDenied 403 for video-synthesis; the 402 credit limit for the deliberately pinned premium model). If the operator's posture changes, the Lead's re-run observes an honest mismatch — the finding re-pins the row (the VAL-015 "crown fails-honestly until then" precedent). The healthy live row's non-empty-content expectation carries the same class of (tiny, recorded) model-behavior risk the VAL-019 answer-term oracles carried.
- **Provider 408 folds into provider-unavailable (recorded taxonomy decision).** The platform's src taxonomy distinguishes a provider `timeout` class; the validation-slice vocabulary folds HTTP 408 into `provider-unavailable` (retryable, provider layer) because the timeout-vs-refusal distinction that MATTERS for this work order is the TOOL-layer one (deadline vs settled refusal). Recorded here for the Lead's review; a future slice may split the class if a live rail documents a 408 family.
- **Message text in the replayed envelopes is representative where the findings preserved only the code token (recorded honestly).** The envelope SHAPES and code tokens are verbatim from the documented live runs; the AllocationQuota message body and the 402/429 message tails are representative (the work order's own 402 message is truncated with an ellipsis). The classifier never depends on message text — only on shapes and code tokens — so classification is unaffected. The live rows' oracles likewise pin classes, never message text.
- **No live provider verification and no PG-backed crown run was possible in this sandbox** (no credentials, no PostgreSQL — by design). The rail binding, the lifecycle binding and the ledger assertions mirror the live-proven VAL-014/015/016/019 crown precedents exactly; the Lead's credentialed re-run is the live verification. Any live divergence is an honest finding to record here.
