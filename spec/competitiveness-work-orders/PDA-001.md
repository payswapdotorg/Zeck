## Objective

Deliver the roadmap §P5 investment 1 (docs/architecture-proposals/ZECK-COMPETITIVENESS-ROADMAP.md): the migration compiler / integration preflight — a developer-facing command that scans an application's active material AI edges, generates the inventory and adapter checklist, detects unsupported edges, and reports the exact gaps BEFORE any code change. The audit methodology is the one the compatibility program already proved: docs/APPLICATION-COMPATIBILITY-TARGET-MATRIX.md (every material AI-backed service, never only the model provider seam) calibrated against the nine certified compat/ integrations.

## Required deliverables

1. **The preflight command** (the `cli/` surface — the existing developer CLI package): input is an application source tree path; output is a typed inventory of detected AI edges (provider clients, model/completion calls, embeddings, reranking, media generation, transcription, voice/realtime, agent/tool AI surfaces) each with file:line provenance, a detection-confidence discipline, and the adapter checklist mapping every edge to the Zeck seam that would serve it.
2. **The gap report**: unsupported edges listed exactly — what was detected, why it has no adapter path, what the migration blocks on. Never a silent skip: NOT-DETECTED is an explicit state distinct from NOT-ANALYZED (the honesty discipline of the compatibility program).
3. **Calibration against the certified corpus**: run the preflight over the nine compat/ targets at their pinned revisions and reconcile the produced inventories against the audited target-matrix edges; every divergence attributed (scanner miss vs matrix drift vs revision change).
4. **Determinism**: the same tree at the same revision produces a byte-identical report (content-addressed; wall-clock and run identities excluded from the digest projection).
5. **Validation suites**: unit oracles over fixture trees (known-edge fixtures per category), discrimination (detector-removal mutants go red), architecture (the command reads application trees and never mutates them; no engine surface under `src/modules/**` changes).
6. **The full existing battery stays green** (typecheck 0; biome 0 errors with the baseline preserved byte-identically; unit/architecture/discrimination/integration/full at or above the baselines on the exact base revision).

## Non-goals / forbidden surfaces

- NO migration execution: the preflight reports, it never edits application code (read-only over the scanned tree).
- NO changes under `src/**` (the preflight is developer tooling, not a Zeck engine change; this work order needs no ACR).
- NO new certification claims: compat/ revisions stay pinned; the preflight inventories, it does not certify.
- `spec/**` and `docs/**` are outside this work order's surfaces (the target matrix is INPUT, not output).
- Workers cannot merge their own PRs; the Lead reviews, runs the independent battery, and merges.
