## Objective

Close the two TL-owned findings reported by the PCR-003 threshold report (owner: Tech Lead), which are prerequisites for clean console projection and helper reachability of this program's own evaluation work:

1. **The console app-to-work-order mapping lacks the PCR/PCS program vocabulary.** `apps/dashboard/validation-lab.ts` `scanApps()` matches only `VAL-\d{3}` work-order tags on the first line of `benchmarks/validation/apps/*/README.md`; the PCR-003 evaluation app had to borrow the parent evidence line's tag (`# economic-recovery-plan-evaluation (VAL-048)`) with a prose explanation that "the console's work-order vocabulary has no PCR-program tag, so the parent evidence line carries it; the true work order is PCR-003". The mapping must recognize the competitiveness program vocabularies (PCR and PCS) as first-class tags with their own spec-path resolution (`spec/competitiveness-work-orders/`), so `PCS-004`'s evaluation app can carry its TRUE work-order tag.

2. **The validation lab does not re-export the PCR-002 seam helpers.** The PCR-003 evaluation app reaches into `experiments/ppr-027/` internals through four-level relative paths (`../../../../experiments/ppr-027/compose`, `driver`, `sweep`, `transport`, `config`) — the PCR-002 wired seam (`compose.ts`) and its evaluation companions are not exposed through the lab's shared surface (`benchmarks/validation/apps/shared/`), so every future evaluation app must re-derive the fragile deep paths.

   - the economic-recovery-plan-evaluation app's README first line is updated to its TRUE tag `PCR-003` (the prose workaround note is removed; the parent-evidence-line attribution stays in the body where it already lives) — this is the acceptance probe for the vocabulary extension;
   - every existing VAL-tagged app, the governed work-order census and all existing console projections remain byte-identical in behavior (the extension is additive; discrimination-tested).
