# PCL-001 — Typed Outcome-Latency Facts: The Per-Failure-Class Evidence Plane

Status: AUTHORIZED (first work order of the P3 program)
Program: zeck-competitiveness-p3
Depends: ACR-010 §2 (normative)
Preferred concurrency: 1 worker
Current governing architecture: v1.0 + D1.0 + E1.0 + E1.1 + ACR-006 + ACR-007 + ACR-008 + ACR-009 + ACR-010

## Objective

Deliver the P3 program's measurement plane: the `OutcomeLatencyFacts` typed artifact (ACR-010 §2) — the closed, optional, per-failure-class, per-route outcome-latency and cost fact block that every later tail-mechanics decision and the PCL-003 evaluation consume read-only. You cannot tune what you cannot measure; this work order builds the measurement truth.

## Required deliverables

1. **The typed artifact** (`src/modules/` at the plane's real home — study the PCS-002 `semantic-fidelity.ts` placement precedent and the module layering per AGENTS.md):
   - the closed vocabularies: outcome class (succeeded-first-attempt | succeeded-after-retry | succeeded-on-fallback | failed-terminal), the per-leg failure-class taxonomy (provider-5xx, provider-timeout, provider-throttle, connection-error, verification-retry, budget-exhausted, policy-denied), progress-delivery mode (event-stream | polled);
   - typed bounded values: per-leg latencies (ms, non-negative, bounded), attempt census by class, polling interval applied, cost lines (total including duplicates; verification cost its own line);
   - explicit provenance on every fact (execution identity, route, revision, clock discipline — the CostClaim explicit-basis pattern);
   - pure boundary checking: both-sides fail-closed pre-validation, absence skips with typed reason, mismatches typed naming both sides;
   - determinism + content addressing: canonical tuple JSON + injected digest, no env/clock/randomness in the fact derivation;
   - absence equivalence: undefined and null both the absent spelling.
2. **Tests**: unit + discrimination suites covering every closed-vocabulary member, every fail-closed boundary, the provenance incoherence rejections, the digest determinism, and the absence-equivalence discipline; architecture tests pinning the module's placement and the no-new-durable-surface law.
3. **The full existing battery stays green** (see Acceptance criteria).

## Non-goals / forbidden surfaces

- NO planner/execution-pipeline changes (the facts are consumed later, by PCL-002/PCL-003 — this work order builds the plane only);
- NO retry/cooldown/polling changes (PCL-002);
- NO evaluation app (PCL-003);
- NO new durable surface beyond the typed artifact; spec/ and docs/ are outside this work order's surfaces;
- Workers cannot merge their own PRs; the Lead reviews, runs the independent battery, and merges.

## Acceptance criteria

- typecheck 0 errors; biome 0 errors (warnings/infos baseline-preserved with byte-identity evidence);
- unit, architecture, discrimination and integration suites at or above the current baselines on the exact base revision;
- every closed-vocabulary member and fail-closed path tested; the digest reproducibility proven in-suite;
- the delivery report states the exact base SHA, branch name, per-suite counts, and the tarball sha256.
