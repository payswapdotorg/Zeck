Current governing architecture: v1.0 + D1.0 + E1.0 + E1.1 + ACR-006 + ACR-007 + ACR-008

## Objective

Implement the `RecoveryPlan` typed artifact and the extended move catalog in the platform failure-recovery plane (`src/platform/failure-recovery/`), exactly as ACR-008 §2–§3 specify. This is the PURE PLANE: types, validation, determinism, tests. NO wiring into any execution/supply path (that is PCR-002) and NO benchmark changes (that is PCR-003).

## Required deliverables

1. **`RecoveryPlan` artifact** (new module in `src/platform/failure-recovery/`, suggested `plan.ts`):
   - a bounded, typed, content-addressable sequence of plan steps; each step carries its move kind, its strategy-selection INPUTS (attribution, recovery context, economics facts) and its selected verdict;
   - the step-count bound rides `RecoveryConfiguration` (extend the existing bounded-configuration type; never ambient, never self-raising);
   - honest terminal failure: a plan ends in `fail-closed` with a typed reason when no admissible move remains; plans never loop and never exceed the bound;
   - deterministic including tie-breaks (invariant 5): same inputs → byte-identical plan; content-addressed plan identity for evidence correlation;
   - idempotent composition on re-run: replaying the same failure context yields the same plan prefix;
   - fail-closed on every unmet precondition and every unknown move kind (never a guess).

2. **Move-catalog extension** (`catalog.ts` + the strategy selection in `strategy.ts`):
   - re-route dimensions grow `model | substrate` → `model | substrate | provider`: the provider-failover dimension consumes the supply plane's OWN typed selection verdict passed in by the caller (read-only facts, exactly the model/substrate re-route discipline); a no-selection outcome makes the dimension inadmissible with a typed reason, never a silent default;
   - `context-repair` move: admissible only for attributed context-corruption failure classes; the caller supplies the typed repair-capability verdict; this plane never edits context itself;
   - `verifier-escalation` move: admissible only for attributed semantic-quality-suspect outcomes; escalates through the EXISTING verification escalation seam (assurance depth may increase, never decrease — invariant 19);
   - every new move carries an explicit-basis `CostClaim` through the shared admissibility machinery (`evaluateAdmissibility` / `governingFacts`) — a move without economic justification is inadmissible.

3. **Plan-composition seam** (pure, no wiring): the function that sequences per-step selection through the EXISTING `selectRecoveryStrategy` — the composer sequences, it never selects. Unknown/absent per-step inputs fail closed.

4. **Tests** (the established discipline — study the existing suites first):
   - unit tests for every new type, bound, validation and fail-closed path;
   - discrimination tests extending `tests/discrimination/failure-recovery.discrimination.test.ts`: determinism (byte-identical plans), tie-break totality, unknown-move fail-closed, bound enforcement, idempotent re-run prefix stability;
   - architecture tests proving no new durable surface, no second execution state machine, no ambient configuration (the continuation-package discipline);
   - keep EVERY existing failure-recovery test green — the single-decision selection surface is preserved byte-for-byte for its existing callers.
