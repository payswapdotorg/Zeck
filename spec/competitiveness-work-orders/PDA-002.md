# PDA-002 — Contract-First SDK Examples + the Support Matrix

## Objective

Deliver the roadmap §P5 investment 2: contract-first SDK examples — stable, idiomatic adapters for popular application seams; a clear support matrix for model, tools, embeddings, media and substrate actuation; executable template tests. The examples/ surface already carries the quickstart-grade pattern; this work order makes the contract coverage complete, honest and executable.

## Required deliverables

1. **The support matrix** (`sdk/` — e.g. `sdk/SUPPORT-MATRIX.md`): per seam category — text/model generation, tools/agents, embeddings, image/audio/video/3D media, substrate actuation, voice/realtime, structured extraction — the contract name, the SDK adapter, the certified example(s), and the known gaps labeled explicitly (supported / certified-example-only / known-gap / NOT RUN).
2. **The idiomatic adapter examples** (`examples/` — extending the existing runnable pattern): each example pinned to the SDK contract it exercises, quickstart-grade, with the adapter checklist inline (what the application hands over and what it gets back).
3. **Executable template tests**: every shipped example compiles and its contract assertions execute in the battery (typecheck-level at minimum; runtime where the existing examples harness pattern supports it) — an example that cannot run is a defect, not an example.
4. **Portability honesty**: the zero-application-file-changes claim stays tied to the compat/ certifications at their pinned revisions; examples never overstate coverage the certifications do not carry.
5. **Validation suites**: unit (contract-assertion oracles), architecture (examples import only the public SDK surface — no `src/modules/**` internals; the public-contract pin), discrimination (a seam-removal mutant goes red).
6. **The full existing battery stays green** (see PDA-001 acceptance standard).

## Non-goals / forbidden surfaces

- NO changes under `src/**`, `spec/**`, `compat/**`, `deploy/**`, `benchmarks/**` (the certification corpus is frozen input; this work order needs no ACR).
- NO new SDK contract surface beyond what the frozen v1.0 contract and existing adapters already expose — the matrix documents and the examples exercise the REAL contract; gaps are reported, never papered over with a new seam.
- NO adoption claims (P5's experiment territory; examples demonstrate, they never claim preference).
- Workers cannot merge their own PRs; the Lead reviews, runs the independent battery, and merges.
