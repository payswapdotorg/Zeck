# VAL-024 — Tenant Isolation and Cross-Application Contamination Validation

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006, VAL-009, VAL-010, VAL-019

## Objective

Deliver the isolation slice: a tenant-isolation application exercising
cross-tenant access control over the REAL platform path — a tenant
submitting work that references another tenant's executions, artifacts,
environments or tool surfaces gets the platform's typed scope violation
(TENANT_SCOPE_VIOLATION per the execution store's locked-row checks),
never data, never effects; cross-APPLICATION contamination (one
application's fixture state, evidence or ledger rows leaking into
another's) is verified absent mechanically. The REAL PostgreSQL
row-scoping (every store query bound by application + tenant) is the
system under test.

## Allowed surfaces

- `benchmarks/validation/apps/tenant-isolation/**`
- `benchmarks/validation/apps/shared/**`
- `benchmarks/validation/platform/**`

## Forbidden

- `src/**` and `spec/**` changes;
- applications importing `src/**`;
- credentials in the repository, logs or reports;
- fabricated model results;
- recording payload bytes in evidence (digest references only).

## Acceptance criteria

1. The application rides the public SDK boundary with a
   repository-reproducible, secret-free configuration and executable
   tests; the corpus declares, per row, the isolation probe (cross-tenant
   read, cross-tenant transition, cross-tenant artifact fetch,
   cross-application state probe) and the expected typed rejection.
2. Deterministic fixtures make every offline row reproducible; the
   isolation probes need no provider (the scope checks are pre-dispatch).
3. A REAL end-to-end integration run over REAL PostgreSQL drives every
   probe: cross-tenant access gets the typed scope violation with zero
   data disclosure (the error evidence carries the boundary, never the
   other tenant's content); cross-application queries return zero rows;
   the isolation journal records each denied probe exactly once.
4. Isolation is verified mechanically: probe assertions on the typed
   error codes; evidence-scan for foreign content; row-count invariants
   per tenant/application before and after the probe battery.
5. Honest economics and latency; payload digests (never payloads) in
   evidence.
6. Discrimination tests prove the probes against controlled fakes
   (forged tenant headers, application-id confusion, artifact-ref
   probing).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN
   boundaries and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions,

## Completion

Complete only after all criteria are evidenced, the PR is merged and
