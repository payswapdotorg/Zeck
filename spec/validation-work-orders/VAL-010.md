# VAL-010 — Text Generation, Structured Extraction and Transformation Applications

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006

## Objective

Deliver the first customer-style application portfolio slice: three real applications (text generation/summarization, structured extraction, transformation) that integrate with Zeck exactly as a customer would — through the public SDK boundary — and prove them end to end against the REAL platform path: the public served API, the REAL model gateway over the REAL BYOK connection and rail adapter, with a REAL provider completion (open-weights route through the operator-authorized OpenRouter access), mechanically verified outcomes, full evidence capture, honest economics and NOT RUN boundaries where access is absent.

## Allowed surfaces

- `benchmarks/validation/apps/text-generation/**`
- `benchmarks/validation/apps/structured-extraction/**`
- `benchmarks/validation/apps/transformation/**`
- `benchmarks/validation/apps/shared/**` (fixture materialization + app-shared contracts)
- `benchmarks/validation/platform/**` (platform-side operator driver contracts: task→request derivation, outcome→verification derivation — network-free, seam-injected)
- validation schemas/tests
- `docs/work-items/VAL-010.md`

## Forbidden

- `src/**` and `spec/**` changes;
- applications importing `src/**` (the customer boundary is the public SDK only);
- credentials in the repository, logs or reports (environment reference by NAME only);
- fabricated model results (absent provider access is a NOT RUN boundary, never a silent pass);
- fixture content that changes corpus task identities (materialization is append-only).

## Acceptance criteria

1. Three applications ride the public SDK boundary with repository-reproducible, secret-free configurations (the VAL-002 harness pattern), each with executable tests and a declared task corpus slice.
2. The platform-side driver composes the REAL models module (model gateway, SQL credential vault, BYOK connection, rail registry, OpenRouter adapter) over the REAL SQL authorities with a REAL injected HTTP transport; absent credential or transport is a classified NOT RUN boundary.
3. A REAL end-to-end integration run (env-gated on the operator-authorized OpenRouter credential) drives a pinned corpus micro-slice through: app submission → canonical lifecycle transitions → REAL model dispatch → mechanically derived verification → app-side deterministic assertions → recorder-consumable evidence.
4. Structured extraction exercises the adapter's native structured-output path (JSON-schema conformance checked mechanically); the invoice corpus slice's deterministic expectations are evaluated by the VAL-008 oracles.
5. Honest economics and latency: rail-reported usage (tokens, USD) and measured latency recorded in the evidence doc; estimated values never masquerade as measured.
6. Discrimination tests prove the driver's derivations against controlled fakes: request mapping, verification verdicts (including oracle failures failing the run), credential absence, admission denial, provider-failure taxonomy propagation.
7. Evidence document records REAL outcomes, timings, costs, NOT RUN boundaries and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification (provider/infrastructure/harness), solutions, recommendation and verification plan. Provider geo-gating and quota facts are recorded as provider-axis evidence only.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
