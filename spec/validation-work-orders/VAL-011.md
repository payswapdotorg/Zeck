# VAL-011 — RAG / Knowledge-Assistant Application

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006, VAL-010

## Objective

Deliver the customer-style RAG/knowledge-assistant application slice: a real retrieval-augmented question-answering application over a synthetic knowledge base, integrated through the public SDK boundary and proven end to end against the REAL platform path (served API, canonical lifecycle, REAL model dispatch through the BYOK connection and rail adapter, mechanically derived verification). Retrieval is measured and recorded (chunk digests, retrieval hits); answer faithfulness is verified against the corpus's own ground-truth answers with mechanical contains/exactness oracles; unsupported questions must be answered with the corpus's declared refusal behavior — never fabricated citations.

## Acceptance criteria

1. The application rides the public SDK boundary with a repository-reproducible, secret-free configuration and executable tests.
2. The synthetic knowledge base materializes deterministically per the VAL-003 fixture recipes (rag knowledge bases: policy + product), with chunk-level digests.
3. Retrieval is deterministic (no external vector store; the fixture's own index), and the dispatched model request carries the retrieved context with provenance markers.
4. A REAL end-to-end integration run (env-gated) drives a pinned corpus slice (rag family rows) through submission → lifecycle → REAL dispatch → mechanical verification → assertions → evidence.
5. Ground-truth answers are checked by mechanical oracles (containsText, refusal detection for unsupported questions, no fabricated section citations); oracle failures fail the run.
6. Honest economics, latency and retrieval-facts (hit digests) recorded; NOT RUN boundaries where access is absent.
7. Evidence document records REAL outcomes, timings, costs, boundaries and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
