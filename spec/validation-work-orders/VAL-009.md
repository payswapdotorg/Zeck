# VAL-009 — Model/Provider Capability Matrix and Access/Readiness Probe

**Status:** DRAFT (Architect-issuable; depends on VAL-001, VAL-002)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-001, VAL-002

## Objective

Build the capability matrix that maps every capability the corpus requires (model:asr, model:vlm, agent:browser, …) to the providers available through the operator's authorized access, plus a readiness probe that verifies usable access (a minimal real call per capability) and records exact gaps as NOT RUN boundaries with the minimum credential/scope required.

## Allowed surfaces

- `benchmarks/validation/capabilities/**`
- validation schemas/tests
- `docs/work-items/VAL-009.md`

## Forbidden

- storing credentials in the repository, logs or reports;
- claiming a capability is ready without a verified probe;
- provider-specific semantics entering the core model.

## Acceptance criteria

1. The matrix enumerates the corpus-declared capabilities and the candidate provider access for each.
2. The readiness probe verifies each provider access with a minimal real invocation (credential via environment reference only).
3. Probe results record latency, cost fact and availability; failures classify (auth/region/quota/network).
4. Capability gaps surface as NOT RUN with the exact missing access requirement for the operator.
5. The matrix resolves every corpus `requiresCapabilities` entry to ready or gap.

## Evidence / issue protocol

Report probe defects with reproduction, classification (provider/infrastructure/harness), solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
