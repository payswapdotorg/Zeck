# VAL-006 — Cost, Latency, Quality, Reliability and Successful-Outcome Accounting

**Status:** DRAFT (Architect-issuable; depends on VAL-001, VAL-004, VAL-005)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-001, VAL-004, VAL-005

## Objective

Build the accounting layer that aggregates recorded runs into the primary economic metric — cost per successfully resolved outcome — with quality/latency/reliability thresholds applied BEFORE an outcome counts as successful, and estimate-vs-measured cost discipline enforced end to end.

## Allowed surfaces

- `benchmarks/validation/accounting/**`
- validation schemas/tests
- `docs/work-items/VAL-006.md`

## Forbidden

- counting failed or below-threshold outcomes as resolved;
- mixing provider estimates into measured totals;
- fabricating cost data for unexecuted baselines.

## Acceptance criteria

1. Run records aggregate into per-application, per-baseline and per-corpus-slice cost/latency/quality/reliability roll-ups.
2. An outcome counts as successfully resolved only when quality, safety, reliability and latency thresholds pass (thresholds declared per corpus task).
3. Cost per successful resolution is computed from measured facts only; estimates are reported separately.
4. Confidence/variance reporting accompanies aggregate comparisons.
5. Accounting outputs feed the cumulative report's economic sections mechanically.

## Evidence / issue protocol

Report accounting defects with reproduction, classification (accounting/validation/provider), solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
