# VAL-005 — Baseline/Comparator Harness for Direct, Optimized and Competing Stacks

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-001

## Objective

Build the reusable comparator harness that runs the SAME customer-style tasks against Zeck and against the comparison baselines the economic hypotheses require: a direct single-provider implementation, a competently optimized non-Zeck implementation, and a relevant competing gateway/router/agent stack — at comparable quality, reliability, safety and latency thresholds.

## Allowed surfaces

- `benchmarks/validation/comparators/**`
- baseline application templates under the validation tree
- validation schemas/tests
- `docs/work-items/VAL-005.md`

## Forbidden

- provider credentials in code;
- weakening the customer boundary for Zeck runs to make comparisons flattering;
- claiming baseline results that were not executed;
- provider-specific semantics entering the core model.

## Acceptance criteria

1. A direct-provider baseline application template executes corpus tasks through the provider's own SDK with identical inputs and evaluation.
2. An optimized non-Zeck baseline template exists (explicit optimization choices documented).
3. A competing-stack baseline template exists for at least one relevant stack, with its integration documented.
4. The comparator runs each baseline and Zeck over the SAME corpus slice with shared evaluation, recording per-run identities.
5. Fair-comparison guards are mechanical: identical inputs, identical assertions, quality/reliability thresholds stated before runs.
6. Missing baseline access is recorded NOT RUN with the exact access requirement surfaced to the operator.

## Evidence / issue protocol

Report comparator defects with reproduction, root-cause classification (Zeck/baseline/harness/provider), viable solutions, recommended solution with trade-offs and verification plan. Never substitute an unavailable baseline with a claim.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
