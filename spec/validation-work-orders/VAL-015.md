# VAL-015 — Image Generation and Image Transformation Application

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap

**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006, VAL-009

## Objective

Deliver the customer-style application portfolio slice for image synthesis: an image-generation application (text-to-image) and an image-transformation application (image-plus-instruction editing), integrated through the public SDK boundary and proven end to end against the REAL platform path with REAL image-model dispatches through the operator-authorized dashscope-international multimodal-generation rail, mechanically verified outcomes, full evidence capture and honest NOT RUN boundaries where authorized access does not exist at run time.

- recording image payloads in evidence (digest references only).

## Acceptance criteria

1. The applications ride the public SDK boundary with repository-reproducible, secret-free configurations and executable tests.
2. Deterministic request fixtures (seeded prompts, deterministic source images synthesized in-code per the VAL-003 recipes) make every dispatch reproducible at the request level; no external media.
3. A REAL end-to-end integration run (env-gated on the authorized image-generation credential) drives a pinned corpus slice through submission → lifecycle → REAL generation/transformation dispatch → mechanical verification → assertions → recorder-consumable evidence.
4. Generated outputs are verified mechanically (valid raster container, declared dimensions, non-empty payload, digest capture); transformed outputs are additionally verified against instruction-relevant mechanical ground truth (e.g., pixel-region change bounds derived from the synthetic source), never against aesthetic judgment.
5. Honest economics and latency; payload digests (never payloads) in evidence.
6. Discrimination tests prove derivations against controlled fakes (fixture digest mismatches, wrong-modality requests, provider failures, malformed raster payloads).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN boundaries and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
