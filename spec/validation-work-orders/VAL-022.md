# VAL-022 — Sandbox/Compute/Substrate Failure and Readiness Validation

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006, VAL-009, VAL-010, VAL-019

## Objective

Deliver the reliability slice for substrate failure: a sandbox-readiness
application exercising compute-substrate failure modes — sandbox
unavailability at submission, mid-execution sandbox loss, substrate
timeout/OOM classification, readiness probing and quarantine — each
attributed and recovered per policy, over the REAL platform path. The
substrate seam is exercised through the platform's declared sandbox/
compute adapter surface with controlled failure injection (the REAL
substrate in this environment is the validation sandbox itself; live
substrate failure cannot be coerced on demand — the injection points are
the adapter seams, with the REAL adapter's healthy path verified live
where it exists).

## Acceptance criteria

1. The application rides the public SDK boundary with a
   repository-reproducible, secret-free configuration and executable
   tests; the corpus declares, per row, the substrate failure mode, the
   expected classification, recovery policy and terminal outcome.
2. Deterministic injection fixtures (fake substrate adapters replaying
   REAL failure shapes — readiness-refused, lost-mid-execution,
   timeout-classified, resource-exhausted) make every offline row
   reproducible.
3. A REAL end-to-end integration run over the REAL platform path drives
   the healthy-substrate rows through the REAL execution lifecycle with
   mechanical verification; the injected-failure rows verify recovery
   policy (retry-with-fresh-sandbox, quarantine-on-repeat-failure,
   honest FAILED with the exact boundary) against the REAL ledger.
4. Readiness semantics are verified mechanically: readiness probes gate
   dispatch (never dispatch to an unready substrate); quarantine
   propagates to future submissions; recovery produces a COMPLETED
   execution with the substrate-failure history journaled.
5. Honest economics and latency; payload digests (never payloads) in
   evidence.
6. Discrimination tests prove the classification against controlled
   fakes (readiness lies, quarantine bypass, dispatch-to-unready,
   misattributed OOM-vs-timeout).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN
   boundaries (live substrate failure coercion) and the executed battery
   honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions,
recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and
