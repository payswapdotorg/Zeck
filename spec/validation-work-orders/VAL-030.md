# VAL-030 — Baseline Freeze and Pre-Learning Control Runs

**Status:** AUTHORIZED / PENDING (dispatch blocked on VAL-026 — the reliability wave's close)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-003, VAL-004, VAL-005, VAL-006, VAL-007, VAL-008, VAL-009, VAL-019, VAL-026

## Objective

Open the longitudinal learning wave by freezing what learning will be
measured AGAINST. Deliver the baseline-freeze slice: a durable,
tamper-evident registry of frozen application-portfolio versions (the
VAL-010..019 app corpus pinned by content digest at the governed head,
together with the golden workload-corpus revisions they run); the
pre-learning CONTROL runs (the frozen baselines replayed over the REAL
platform path with learning explicitly inert — no reuse, no caching
hints, no competence shortcuts — the reference arm every later
learning claim must beat); and the mechanical verification that makes
the freeze trustworthy: re-run equivalence (a control re-run over the
deterministic fixtures reproduces the recorded trajectory-digest
equivalence class), ledger exactly-once (every control run is ONE
immutable longitudinal-experiment identity per the VAL-007 discipline),
and freeze integrity (any mutation of a frozen app version, workload
revision or recorded trajectory FAILS the digest check — a drifting
baseline is unrepresentable).

The control runs ride the proven crown pattern: the public SDK
boundary, the recorder's full trajectory capture, the comparator
harness's equivalence classes, the accounting rails' honest economics,
and the REAL provider dispatches where the corpus rows demand them
(env-gated, BYOK, measured — never fabricated).

## Forbidden

- `src/**` and `spec/**` changes;
- applications importing `src/**`;
- mutating any frozen baseline artifact after its registry commit
  (the registry is append-only; a correction is a NEW registry
  revision, never an edit);
- credentials in the repository, logs or reports;
- fabricated model results;
- recording payload bytes in evidence (digest references only).

## Acceptance criteria

1. The application rides the public SDK boundary with a
   repository-reproducible, secret-free configuration and executable
   tests; the corpus declares, per row, the baseline manifest entry
   (app digest + workload revision), the expected terminal and the
   trajectory-digest equivalence class the control run must reproduce.
2. Deterministic fixtures make every offline row reproducible; the
   frozen-baseline manifest is content-addressed (digests over the
   pinned artifacts, never the artifacts copied).
3. A REAL end-to-end integration run (env-gated) drives a pinned
   control corpus over the REAL platform path: control runs complete,
   their trajectories are recorded through the REAL recorder, and the
   longitudinal ledger holds exactly ONE immutable run identity per
   control run.
4. Mechanical verification per row: freeze integrity (manifest digest
   agreement), re-run equivalence (the recorded trajectory digest
   reproduces), ledger exactly-once, accounting honesty — probed
   adversarially (a mutated baseline, a duplicated ledger identity and
   a drifting re-run each FAIL mechanically).
5. Honest economics and latency (measured on the live rows,
   none-reported honestly offline); payload digests (never payloads)
   in evidence.
6. Discrimination tests prove the freeze against controlled fakes
   (mutated baseline artifact, learning-contaminated run masquerading
   as control, ledger duplication, trajectory drift between re-runs).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN
   boundaries and the executed battery honestly.
