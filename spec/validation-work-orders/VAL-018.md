# VAL-018 — Multimodal Transformation and 3D Generation/Rendering Application

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006, VAL-009

## Objective

Deliver the customer-style application portfolio slice for cross-modal transformation and 3D: a multimodal-transformation application (image → structured description → derived media, chaining the proven vision and image-generation rails) and a 3D generation/rendering application, integrated through the public SDK boundary and proven end to end against the REAL platform path with REAL chained dispatches where operator-authorized access exists, mechanically verified outcomes, full evidence capture and honest NOT RUN boundaries for 3D generation/rendering where no authorized provider rail exists — surfacing the exact missing 3D access requirement (provider/model, why needed, experiment unlocked, minimum credential) to the operator per the roadmap's provider-access policy rather than substituting a fabricated equivalent.

## Acceptance criteria

1. The applications ride the public SDK boundary with repository-reproducible, secret-free configurations and executable tests.
2. Deterministic request/source fixtures (synthetic images per the VAL-003 recipes, seeded prompts) make every dispatch reproducible at the request level; no external media.
3. A REAL end-to-end integration run (env-gated on the authorized chained credentials) drives a pinned corpus slice through submission → lifecycle → REAL chained multimodal dispatch → mechanical verification → assertions → recorder-consumable evidence; the 3D sub-slice is an honest recorded NOT RUN boundary until operator-authorized 3D access exists (its offline paths, derivations and discrimination tests still execute).
4. Transformation chains are verified mechanically at each stage (vision answers against fixture ground truth; derived-media outputs by container validity, dimensions and digest capture) with per-stage provenance in evidence; 3D outputs, when a rail later exists, verify by container validity and digest.
5. Honest economics and latency (per-stage and end-to-end); payload digests (never payloads) in evidence.
6. Discrimination tests prove derivations against controlled fakes (fixture digest mismatches, wrong-modality requests, provider failures at each chain stage, malformed payloads, chain-abort propagation).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN boundaries (including the surfaced 3D access requirement) and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
