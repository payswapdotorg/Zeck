# VAL-043 — Relevant Competing Gateway/Router/Agent-Stack Benchmark

**Status:** AUTHORIZED / PENDING (dispatch blocked on VAL-030 + VAL-040)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-040, VAL-030

## Objective

Deliver the COMPETING-STACK arm: the frozen app portfolio replayed
through a relevant competing gateway/router/agent stack (the
comparator harness's competing-stack arm — a real routing product or
agent framework a customer could use instead of Zeck), configured
per its own documented best practices, so the economic comparison
includes the actual market alternative. The competitor's pricing is
pinned through the VAL-040 manifest discipline (public list prices,
digest-pinned revisions — negotiated rates forbidden); its
configuration is declared exhaustively (model selection, routing
rules, retry policies) and reproducible from the repository; every
run executes the VAL-040 experiment protocol (fixed-quality /
fixed-cost arms, normalized micro-USD per resolved outcome, Wilson
confidence, pre-registered corpus slices, minimum sample sizes).

The verification core: an undocumented configuration toggle FAILS the
conformance oracle; a competitor behavior change between runs (nondeterministic
routing) FAILS the reproducibility oracle unless declared as honest
variance with confidence carried; normalization/manifest oracles as
in VAL-041/042. Live rows (env-gated, BYOK, measured) drive REAL
competing-stack rounds; offline rows replay recorded traces.

## Allowed surfaces

- `benchmarks/validation/apps/economic-controls-competing/**`

- `docs/work-items/VAL-043.md`

## Forbidden

- `src/**`, `spec/**`, `benchmarks/validation/platform/**`,
  `benchmarks/validation/apps/shared/**` and any other application's
  directory changes (additive and disjoint only);
- applications importing `src/**`;
- undocumented competitor configuration (the declaration is
  exhaustive by construction);
- negotiated/bulk pricing in any manifest (public list prices only);
- credentials in the repository, logs or reports;
- fabricated model results;
- recording payload bytes in evidence (digest references only).

## Acceptance criteria

1. The application rides the public SDK boundary with a
   repository-reproducible, secret-free configuration and executable
   tests; the corpus declares, per row, the frozen portfolio
   revision, the arm manifest entry (competing-stack kind, the
   declared configuration, pinned price revisions, arm kind,
   statistical minimums) and the expected normalized outcome.
2. Deterministic fixtures make every offline row reproducible; frozen
   portfolio artifacts referenced by digest; the competitor
   configuration declaration is content-addressed alongside the price
   manifests.
3. A REAL end-to-end integration run (env-gated) drives the
   competing stack over representative portfolio slices with REAL
   dispatches through the competitor's real interface: runs complete,
   economics measured by the REAL accounting rails, normalized
   comparisons recorded through the REAL recorder.
4. Mechanical verification per row: configuration conformance (an
   undeclared toggle FAILS), reproducibility (nondeterministic
   competitor behavior either reproduces or carries declared honest
   variance with confidence), normalization integrity, protocol
   conformance, manifest integrity.
5. Honest economics and latency (measured on live rows, none-reported
   honestly offline); payload digests (never payloads) in evidence.
6. Discrimination tests prove the arm against controlled fakes
   (undeclared-configuration masquerade, silent routing change,
   mixed-currency conflation, estimate-backed cost, post-hoc arm
   exclusion, sample-size violation).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN
   boundaries and the executed battery honestly.
