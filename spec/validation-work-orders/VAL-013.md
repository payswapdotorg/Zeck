# VAL-013 — Long-Running / Resumable Agent Application

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-012

## Objective

Deliver the customer-style long-running/resumable agent slice: a real agent application whose execution spans checkpointed progress (durable checkpoints with digests and positions), pause/resume across external waits, and crash-recovery resume of an already-RUNNING execution — riding the REAL long-running surface (checkpoints, leases, wake-ups, resume-recorded/resume-denied ledger events) through the public SDK boundary, with REAL model dispatch(es) and mechanically verified recovery semantics.

## Allowed surfaces

- `benchmarks/validation/apps/long-running/**`
- `benchmarks/validation/apps/shared/**`
- `benchmarks/validation/platform/**`
- validation schemas/tests
- `docs/work-items/VAL-013.md`

## Forbidden

- `src/**` and `spec/**` changes;
- applications importing `src/**`;
- credentials in the repository, logs or reports;
- fabricated model results or fabricated checkpoint progress;
- simulating crash recovery without the REAL durable ledger.

## Acceptance criteria

1. The application rides the public SDK boundary with repository-reproducible, secret-free configuration and executable tests.
2. A REAL end-to-end run (env-gated) drives a pinned long-running corpus slice through submission → lifecycle → REAL dispatch → durable checkpoints (digest + position) → an external wait (wait-user/wait-human with interruption) → resume → completion, with every checkpoint/wake-up/resume fact on the ledger.
3. Crash-recovery discrimination: a resume attempt on a healthy RUNNING execution is DENIED and journaled (resume-denied) — never a silent double-drive; a genuine interruption → resume path completes with verified continuity (no lost or duplicated work).
4. Checkpoint integrity: the recorded checkpoint digests match the recomputed digests (tamper-evident continuity).
5. Honest economics, latency, and per-checkpoint facts recorded; NOT RUN boundaries where access is absent.
6. Discrimination tests over controlled fakes for every recovery branch.
7. Evidence document records REAL outcomes, timings, costs, boundaries and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
