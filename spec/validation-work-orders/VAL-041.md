# VAL-041 — Direct-Provider Control Runs Across the Complete App Portfolio

**Status:** AUTHORIZED / PENDING (dispatch blocked on VAL-030 + VAL-040 — the protocol substrate and the longitudinal baseline must both be complete)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-040, VAL-030

## Objective

Deliver the DIRECT-PROVIDER control arm of the economic validation: the
complete customer-style app portfolio (the frozen VAL-030 baseline
revisions) replayed with providers called DIRECTLY — no Zeck agent
platform, no gateway middle layer, no reuse/cache shortcuts — so every
later Zeck economic claim has the honest "what it would cost and
quality-attain without us" reference. Every run executes the VAL-040
experiment protocol: fixed-quality arms measure cost-to-attain the
declared threshold, fixed-cost arms measure quality-attained-within
budget, all economics normalized through the VAL-040 rails (micro-USD
per successfully resolved outcome, measured facts only, pinned
list-price manifest revisions), all comparisons carrying Wilson
confidence, pre-registered corpus slices with minimum sample sizes.

The verification core: a run that quietly rode a platform shortcut (or
any non-direct path) FAILS the arm-conformance oracle mechanically; a
mixed-currency or estimate-backed cost FAILS the normalization oracle;
an unpinned price FAILS the manifest oracle. Live rows (env-gated,
BYOK, measured — never fabricated) drive REAL direct provider rounds
across representative portfolio slices; offline rows replay recorded
control traces deterministically.

## Forbidden

- `src/**`, `spec/**`, `benchmarks/validation/platform/**`,
  `benchmarks/validation/apps/shared/**` and any other application's
  directory changes (this slice is additive and disjoint; importing
  existing modules is fine, modifying them is not);
- applications importing `src/**`;
- credentials in the repository, logs or reports;
- fabricated model results;
- recording payload bytes in evidence (digest references only).

## Acceptance criteria

1. The application rides the public SDK boundary with a
   repository-reproducible, secret-free configuration and executable
   tests; the corpus declares, per row, the frozen portfolio revision,
   the arm manifest entry (direct-provider kind, pinned price
   revision, fixed-quality or fixed-cost arm, statistical minimums)
   and the expected normalized outcome.
2. Deterministic fixtures make every offline row reproducible; frozen
   portfolio artifacts are referenced by content digest (never
   copied); price manifests are the VAL-040 pinned revisions.
3. A REAL end-to-end integration run (env-gated) drives the
   direct-provider arm over representative portfolio slices with REAL
   provider dispatches: runs complete, economics are measured by the
   REAL accounting rails, normalized comparisons recorded through the
   REAL recorder.
4. Mechanical verification per row: direct-path conformance (the
   provider dispatch carries no platform/gateway artifacts — probed
   adversarially: a shortcut-riding row FAILS), normalization
   integrity, protocol conformance, manifest integrity.
5. Honest economics and latency (measured on live rows, none-reported
   honestly offline); payload digests (never payloads) in evidence.
6. Discrimination tests prove the control against controlled fakes
   (platform-shortcut masquerade, mixed-currency conflation,
   estimate-backed cost, post-hoc arm exclusion, sample-size
   violation).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN
   boundaries and the executed battery honestly.
