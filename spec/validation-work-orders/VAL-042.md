# VAL-042 — Strong Manually Optimized Non-Zeck Baseline

**Status:** AUTHORIZED / PENDING (dispatch blocked on VAL-030 + VAL-040)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-040, VAL-030

## Objective

Deliver the STRONG OPTIMIZED NON-ZECK baseline arm: the frozen app
portfolio replayed through a manually optimized direct stack — the
best honest engineering a customer could do WITHOUT Zeck (explicit
model routing by task class, prompt compression, response caching
where semantically safe, batched throughput, provider-side
optimization features) — so the economic comparison is against the
STRONGEST realistic alternative, not a strawman. The arm declares its
optimization inventory explicitly (each optimization named, bounded,
and priced through the VAL-040 pinned manifests); every run executes
the VAL-040 experiment protocol (fixed-quality / fixed-cost arms,
normalized micro-USD per resolved outcome, Wilson confidence,
pre-registered corpus slices, minimum sample sizes).

The verification core: an undeclared optimization (something the
baseline does that its inventory does not name) FAILS the
conformance oracle; a semantically-UNSAFE optimization (cache reuse
across rows where correctness demands freshness) FAILS the safety
oracle; normalization/manifest oracles as in VAL-041. Live rows
(env-gated, BYOK, measured) drive REAL optimized rounds; offline rows
replay recorded traces deterministically.

## Forbidden

- `src/**`, `spec/**`, `benchmarks/validation/platform/**`,
  `benchmarks/validation/apps/shared/**` and any other application's
  directory changes (additive and disjoint only);
- applications importing `src/**`;
- undeclared optimizations (the inventory is exhaustive by
  construction — a discrimination test proves it);
- credentials in the repository, logs or reports;
- fabricated model results;
- recording payload bytes in evidence (digest references only).

## Acceptance criteria

1. The application rides the public SDK boundary with a
   repository-reproducible, secret-free configuration and executable
   tests; the corpus declares, per row, the frozen portfolio
   revision, the arm manifest entry (optimized-baseline kind, the
   declared optimization inventory, pinned price revisions, arm kind,
   statistical minimums) and the expected normalized outcome.
2. Deterministic fixtures make every offline row reproducible; frozen
   portfolio artifacts referenced by digest; optimization inventory
   is content-addressed alongside the price manifests.
3. A REAL end-to-end integration run (env-gated) drives the optimized
   baseline over representative portfolio slices with REAL provider
   dispatches through the declared optimizations: runs complete,
   economics measured by the REAL accounting rails, normalized
   comparisons recorded through the REAL recorder.
4. Mechanical verification per row: inventory conformance (an
   undeclared optimization FAILS — probed adversarially), cache-safety
   (unsafe reuse FAILS), normalization integrity, protocol
   conformance, manifest integrity.
5. Honest economics and latency (measured on live rows, none-reported
   honestly offline); payload digests (never payloads) in evidence.
6. Discrimination tests prove the baseline against controlled fakes
   (undeclared-optimization masquerade, unsafe cache reuse,
   mixed-currency conflation, estimate-backed cost, post-hoc arm
   exclusion, sample-size violation).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN
   boundaries and the executed battery honestly.
