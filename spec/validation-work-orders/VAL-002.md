# VAL-002 — Customer-Style SDK/API Integration Harness

**Status:** PLANNED (becomes dispatchable after VAL-001)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-001

## Objective

Build the reusable harness and sample-application skeleton that integrates with Zeck exclusively through the public developer surface, with reproducible configuration, task execution, evidence capture and outcome assertions.

## Allowed surfaces

- `benchmarks/validation/apps/**`
- `benchmarks/validation/harness/**`
- public SDK/API examples required for validation
- validation configuration and tests
- `docs/work-items/VAL-002.md`

## Forbidden

- direct calls into internal Zeck modules as the acceptance path;
- changes to frozen product contracts;
- provider credentials in code;
- app-specific functionality outside harness needs.

## Acceptance criteria

1. A minimal application can invoke Zeck through the supported customer integration boundary.
2. Harness supports request submission, asynchronous completion, result retrieval and error reporting where those public modes exist.
3. App configurations are isolated from secrets and reproducible from repository files plus environment secrets.
4. Every run receives a stable experiment/run identity and records application and Zeck revisions.
5. Harness can execute deterministic assertions against returned outcomes and environment state where relevant.
6. Harness can emit evidence consumable by the universal recorder and final report.
7. A clean-checkout sample app can be bootstrapped without internal source imports.

## Evidence / issue protocol

Report all integration defects with reproduction, API request/response evidence, root-cause classification, viable solutions, recommended solution and verification plan. Missing provider/model access remains NOT RUN and must be surfaced.
