## Objective

Deliver the customer-style application portfolio slice for agentic and human-in-the-loop workloads: a focused suite of small applications — customer-service triage, browser-use, computer-use, research, coding and operations — each with a declared task corpus, tool-surface integration through the public SDK boundary and, where the workload demands it, genuine human-in-the-loop decision cycles (approval gates, escalations and supervised continuations), proven end to end against the REAL platform path with REAL model dispatches through the proven operator-authorized text rails (tool-using agent patterns per the VAL-012 precedent) and mechanically verified outcomes, full evidence capture and honest NOT RUN boundaries for any external surface whose authorized access does not exist at run time.

## Forbidden

- `src/**` and `spec/**` changes;
- applications importing `src/**`;
- credentials in the repository, logs or reports;
- fabricated model results or fabricated human decisions;
- recording payload bytes in evidence (digest references only).

## Acceptance criteria

1. Every application in the suite rides the public SDK boundary with repository-reproducible, secret-free configurations and executable tests; each declares its task corpus, expected/forbidden outcomes, quality rubric, safety constraints, latency bounds and economic accounting per the roadmap's customer-style boundary.
2. Corpus rows are deterministic where the workload allows (fixture inputs per the VAL-003 recipes); external-world surfaces (browser/computer environments) run against controlled local fixtures or recorded environments, never live third-party systems, unless an operator-authorized rail exists.
3. A REAL end-to-end integration run (env-gated on the authorized text/tool rails) drives a pinned corpus slice through submission → lifecycle → REAL dispatch with tool use → mechanical verification → assertions → recorder-consumable evidence for each application.
4. Outcomes are verified mechanically (corpus-declared expectations, tool-effect assertions against fixture state, HITL decision-loop assertions: approvals gate effects, escalations route correctly, supervised continuations resume exactly once); browser/computer-use surfaces verify against controlled environment fixtures with honest NOT RUN boundaries where no authorized live surface exists.
5. Honest economics and latency; payload digests (never payloads) in evidence.
6. Discrimination tests prove derivations against controlled fakes (fixture digest mismatches, wrong-tool requests, provider failures, unauthorized-effect rejection, HITL bypass attempts).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN boundaries and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
