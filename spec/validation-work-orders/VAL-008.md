# VAL-008 — Evaluation/Scoring Engine and Error Taxonomy

**Status:** DRAFT (Architect-issuable; depends on VAL-003, VAL-004)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-003, VAL-004

## Objective

Build the evaluation engine that scores recorded runs against the corpus expectations: deterministic oracles, tolerance bands and rubric-based evaluation, plus the unified error taxonomy for outcome classification (root-cause families aligned with the issue protocol).

## Allowed surfaces

- `benchmarks/validation/evaluation/**`
- validation schemas/tests
- `docs/work-items/VAL-008.md`

## Forbidden

- converting NOT RUN boundaries into passes;
- evaluator prompts that can be steered by the evaluated content;
- weakening corpus expectations to raise scores.

## Acceptance criteria

1. Deterministic evaluation executes the corpus oracles exactly (containsText, output shapes, effect assertions).
2. Tolerance evaluation applies the stated numeric bands with recorded measurements.
3. Rubric evaluation scores the corpus rubrics with reproducible judge configuration (judge identity/config recorded per evaluation).
4. The error taxonomy classifies failures into the root-cause families with mechanical dispatch rules.
5. Scoring results attach to run records as evaluation facts.

## Evidence / issue protocol

Report evaluator defects with reproduction, classification, solutions, recommendation and verification plan. Judge drift is recorded, never silently absorbed.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
