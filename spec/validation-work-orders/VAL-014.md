# VAL-014 — Voice Input/Output and Realtime Voice Application

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006, VAL-009

## Objective

Deliver the customer-style application portfolio slice for voice: a speech-to-text application, a text-to-speech application and a realtime voice-loop application, integrated through the public SDK boundary and proven end to end against the REAL platform path with REAL voice-model dispatches where operator-authorized access exists (ASR through the operator-authorized dashscope-international dedicated task API; TTS through an operator-authorized rail), mechanically verified outcomes, full evidence capture and honest NOT RUN boundaries for any modality whose authorized access does not exist at run time (surfacing the exact missing access requirement per the roadmap's provider-access policy).

- credentials in the repository, logs or reports;
- fabricated model results;
- recording audio payloads in evidence (digest references only).

## Acceptance criteria

1. The applications ride the public SDK boundary with repository-reproducible, secret-free configurations and executable tests.
2. Deterministic synthetic audio fixtures materialize exactly per the VAL-003 fixture recipes (in-code WAV synthesis; no external media), reusing or extending the shared media library.
3. A REAL end-to-end integration run (env-gated on the authorized voice credentials) drives a pinned corpus slice through submission → lifecycle → REAL ASR/TTS dispatch → mechanical verification → assertions → recorder-consumable evidence; realtime voice is proven through the platform's session/resumability semantics with honest NOT RUN boundaries where no authorized realtime rail exists.
4. ASR transcripts are verified against the fixtures' ground-truth annotations; TTS outputs are verified mechanically (container/codec validity, non-empty payload, digest capture) since byte-level audio ground truth is not provider-stable; realtime loop behavior is verified against declared session expectations.
5. Honest economics and latency; payload digests (never payloads) in evidence.
6. Discrimination tests prove derivations against controlled fakes (fixture digest mismatches, wrong-modality requests, provider failures, malformed audio).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN boundaries and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
