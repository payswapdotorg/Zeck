# VAL-004 — Universal Trace, Trajectory, Environment-State and Evidence Recorder

**Status:** PLANNED (becomes dispatchable after VAL-001)
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-001

## Objective

Create the cross-application recorder that captures the complete customer-style execution trajectory and resulting environment state without storing secrets. It must support later root-cause analysis, deterministicization experiments and economic accounting.

## Required run record

At minimum capture application revision, Zeck revision, corpus/task identity, environment class, policy/capabilities, model/reasoning choice, exposed and used tools, context/cache events, agent count, substrate/readiness, retries/escalations, verification, final output, resulting environment state, latency, direct execution cost and total successful-resolution cost where measurable.

## Allowed surfaces

- `benchmarks/validation/recorder/**`
- validation schemas/storage/export tooling
- validation-specific tests
- `docs/work-items/VAL-004.md`

## Forbidden

- secrets, credentials or raw sensitive payloads in durable evidence;
- replacing Zeck's authoritative execution/evidence state;
- making validation telemetry an execution authority;
- provider-specific telemetry semantics leaking into the core model.

## Acceptance criteria

1. Every validation run receives a stable immutable run identity.
2. Run records link application revision, Zeck revision, task/corpus version and environment identity.
3. Recorder captures enough trajectory data to reconstruct model/tool/agent/substrate decisions and retries.
4. Resulting environment state can be recorded for outcome-state validation without pretending a response string is proof of effect.
5. Cost and latency facts can be attached without conflating provider estimates with measured charges.
6. Secret/credential redaction is enforced and tested.
7. Records are append-only or versioned so historical experiments remain reproducible.
8. Export format is sufficient for longitudinal diffing and economic analysis.

## Issue / solution protocol

For telemetry gaps distinguish Zeck instrumentation defects, provider observability limits, application instrumentation gaps and evaluator limitations. Provide viable remedies and a recommended option with trade-offs.
