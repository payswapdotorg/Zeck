# VAL-020 — Provider/Model/Tool Failure Attribution and Recovery

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006, VAL-009, VAL-010, VAL-019

## Objective

Deliver the reliability slice for failure attribution: a failure-injection
and attribution application exercising the platform's provider/model/tool
failure taxonomy end to end — transport failures, provider error envelopes
(quota, rate-limit, invalid-request, access-denied), empty/degenerate
completions, tool-execution failures and timeouts — each attributed to the
correct layer (transport vs provider vs tool vs platform) with the correct
retryability classification, driven through bounded retry/recovery
policies over the REAL platform path, proven with REAL provider dispatches
where operator-authorized access exists (the failure modes the live rails
actually produce, honestly captured) and controlled fault injection where
the rail cannot be coerced into a specific failure on demand.

## Acceptance criteria

1. The application rides the public SDK boundary with a
   repository-reproducible, secret-free configuration and executable tests;
   the failure corpus declares, per row, the injected/observed failure
   class, the expected attribution layer, retryability and the expected
   terminal + recovery outcome.
2. Deterministic fault-injection fixtures (fake transports/rails that
   replay REAL provider failure envelope shapes observed in prior live
   runs — dashscope AllocationQuota/AccessDenied envelopes, OpenRouter
   credit-limit 402s, empty-content 200s — per the documented rail
   findings) make every offline row reproducible.
3. A REAL end-to-end integration run (env-gated on the authorized rails)
   drives the attributable failure classes the live rails genuinely
   produce and verifies the platform's honest handling: classification,
   bounded retry, terminal state, journal evidence.
4. Recovery semantics are mechanically verified: retryable failures get
   bounded retries with backoff (no infinite loops); non-retryable
   failures never retry; recovery-after-retry produces a COMPLETED
   execution with the retry history journaled exactly once per attempt.
5. Honest economics and latency; payload digests (never payloads) in
   evidence.
6. Discrimination tests prove the attribution logic against controlled
   fakes (envelope-shape confusion, wrong-layer attribution, retry-policy
   boundary violations, timeout-vs-refusal classification).
7. Evidence document records REAL outcomes, timings, costs, NOT RUN
   boundaries and the executed battery honestly.
