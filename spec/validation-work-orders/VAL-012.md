# VAL-012 — Tool-Using Agent and Multi-Step Business Workflow Application

**Status:** AUTHORIZED / PENDING
**Program:** Zeck Validation Roadmap
**Assurance:** HIGH_ASSURANCE
**Dependencies:** VAL-002, VAL-003, VAL-004, VAL-006, VAL-010

## Objective

Deliver the customer-style tool-using agent slice: a real multi-step business-workflow application whose governed agent invokes declared tools (deterministic, in-lab tool surface) across multiple model dispatches, integrated through the public SDK boundary and proven end to end against the REAL platform path. Tool invocations ride the execution ledger's step-event vocabulary (tool-requested/tool-result) through the platform's own seams; the multi-step lifecycle (wait-tool/resume) is exercised on the REAL state machine; final outcomes are verified mechanically against the corpus's expected workflow results.

## Forbidden

- `src/**` and `spec/**` changes;
- applications importing `src/**`;
- credentials in the repository, logs or reports;
- fabricated model results or fabricated tool outcomes;
- real external side effects (tools are deterministic in-lab surfaces).

## Acceptance criteria

1. The application rides the public SDK boundary with repository-reproducible, secret-free configuration and executable tests.
2. The tool surface is declared and deterministic (request/result contracts, no network), materialized per the corpus scenario's environment fixtures.
3. A REAL end-to-end integration run (env-gated) drives a pinned corpus slice (tools + workflow family rows) through submission → lifecycle INCLUDING a genuine multi-step wait-tool/resume cycle on the REAL state machine → REAL model dispatch(es) with tool-result context → mechanical verification → assertions → evidence.
4. Tool invocations are recorded as ledger step events (the platform's own vocabulary) with digests; the final workflow outcome is verified against the corpus's expected result.
5. Provider-failure mid-workflow propagates honestly (failed run, no partial-success shortcut).
6. Honest economics (per-dispatch usage summed), latency, and step-event facts recorded; NOT RUN boundaries where access is absent.
7. Evidence document records REAL outcomes, timings, costs, boundaries and the executed battery honestly.

## Evidence / issue protocol

Report defects with reproduction, classification, solutions, recommendation and verification plan.

## Completion

Complete only after all criteria are evidenced, the PR is merged and validation state is finalized.
