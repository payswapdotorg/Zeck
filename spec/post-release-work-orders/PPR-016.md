## Phase A — credential and provider preflight

For every relevant existing provider rail:
1. Verify whether the authorized environment actually contains the required credential.
2. Never print, store, or commit secret values.
3. Missing credentials are NOT RUN.
4. Preserve region, quota, DNS and authorization boundaries honestly.
5. When credentialed, begin with the smallest real provider probe, then run the family validation.
6. Do not widen permissions merely to make a test pass.

Do not add a new credential materialization path without a separately governed change.

## Phase B — complete existing rails

Run the full real path where access permits:
provider probe → capability admission → execution → verification → evidence → route/cost facts → family validation.

At minimum evaluate the currently recorded Qwen voice, Qwen image generation, Qwen video, OpenRouter image recognition, VLM and multimodal rails, plus any other already-authorized rail discovered during reconciliation.

For video, explicitly measure the quota boundary rather than burning quota on redundant probes.

OpenAI remains region-blocked unless the actual authorized egress changes.

## Phase C — realtime voice decision gate

Realtime voice is separate from ASR/TTS and separate from LiveKit transport.

The Tech Lead must research whether an existing authorized provider can satisfy the neutral RealtimeRail contract and work with the existing LiveKit/socket composition without leaking provider semantics.

If no admissible provider-backed realtime model rail exists, record the result as a blocked research boundary and do not implement speculative realtime semantics.

If a concrete provider is identified, prepare a successor governed Work Order for the provider adapter and realtime journey extension. Do not silently implement it inside PPR-016.

## Phase D — 3D, browser-use and computer-use

Keep these as separate capability gaps.

3D stays NOT RUN while no authorized model:three-d provider exists.
Browser-use and computer-use stay fixture-proven until a real operator-authorized rail exists.
If research identifies a credible new provider or open-source adapter, record the candidate and trade-offs and prepare a successor Work Order rather than expanding PPR-016 into a speculative implementation.
