# PPR-003 — Public User-Journey Simulation and Acceptance Harness

**Status:** AUTHORIZED / WAVE A  
**Program:** zeck-post-release-public-productization  
**Base:** current governed main at dispatch

## Objective

Create a repeatable acceptance harness for the actual public Zeck experience and convert every material finding into the smallest valid correction Work Order.

## Journeys

1. discover;
2. capability discovery;
3. sandbox start;
4. first text execution;
5. execution inspection;
6. evidence/cost;
7. validation rerun;
8. compare;
9. export/reproduce;
10. trust/limits;
11. agent onboarding;
12. production/deployment.

## Verification dimensions

- reachability;
- navigation;
- browser console errors;
- exact deployment revision;
- real sandbox execution;
- validation rerun;
- compare/export;
- provider-gated/NOT RUN disclosure;
- keyboard/focus;
- desktop/tablet/mobile;
- reduced motion;
- secret safety.

## Capability coverage

Every workload family in `docs/developer/machine/capability-manifest.json` must map to:
- discovery location;
- availability state;
- example/runnable path;
- provider/access explanation.

Provider-gated capability must never be reported as live success without required access.

## Findings

Every finding records:
- journey/step;
- exact surface;
- observed vs expected;
- severity;
- defect class;
- evidence;
- viable solutions;
- recommended solution/trade-offs;
- verification requirement.

## Completion

Run against the real deployed URL and exact revision. Any material defect becomes the input to the next smallest-valid correction Work Order.
