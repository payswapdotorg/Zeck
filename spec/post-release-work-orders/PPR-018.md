# PPR-018 — Aider Zeck-Complete Application Proof

Status: AUTHORIZED / READY FOR TECH-LEAD DISPATCH
Program: zeck-application-compatibility-proof
Authorization date: 2026-09-27
Preferred concurrency: 1 worker
Target: Aider coding assistant
Depends: PPR-017
Final-certification dependency: PPR-018A

## Objective

Produce the first real external application proof that Aider can remove its direct AI-provider execution infrastructure and operate with Zeck as its sole AI execution authority for the declared representative corpus.

## Integration strategy

Pin an exact Aider upstream revision.

Prefer Aider's existing model abstraction/LiteLLM seam rather than forking broad Aider internals.

Use the ACR-007 Application Delegation Boundary. The application adapter must translate Aider's material AI execution edges to Zeck without importing Zeck internals or reproducing policy, capability, budget, routing, retry, verification, evidence or optimization authority.

The integration must cover every AI call Aider makes for the declared tasks, including auxiliary, summarization, weak-model, cache-warming or other model paths actually active in the pinned runtime.

Aider may retain repository, filesystem and Git domain operations. Those are not direct AI-provider execution unless they themselves invoke an AI service.

Development may proceed concurrently with PPR-018A and PPR-019. Do not mark the proof complete until the reusable PPR-018A runner/certification harness is merged and the final evidence binds to that harness.

## Proof

Run the complete ACR-006/ACR-007 compatibility battery:

- exact upstream and integration revision pins;
- complete execution-edge inventory;
- provider credential removal from the certified Aider runtime;
- direct-provider egress block;
- representative coding corpus;
- Zeck trace/evidence correlation for every material edge;
- duplicate/retry/timeout/provider-failure validation;
- direct and strong optimized non-Zeck baselines;
- cost per successfully resolved outcome and quality-adjusted cost;
- latency and tail latency;
- customization and provider portability;
- deterministic/reuse opportunity measurement;
- capability-discovery-driven avoided implementation measurement where applicable;
- telemetry/explainability completeness;
- static/runtime no-bypass audit;
- reproducibility.

Do not claim AI_EXECUTION_COMPLETE if any material AI path remains direct, provider-specific, fixture-only, unverified or hidden behind a proxy.

## Website demonstration

Register Aider in the Demo Mirror only with the evidence status produced by the compatibility framework.

The certified demo must run the exact pinned Aider integration/runtime used for certification, not a synthetic coding response.

Expose the real application result and its Zeck execution trace, including route/plan, usage/cost/latency, verification and reproducibility facts where available.

## Evidence

Create deploy/evidence/ppr-018.json with exact upstream revision, integration revision, execution graph, edge coverage, Zeck execution identifiers, direct-provider egress result, quality/reliability/economic measurements, telemetry, customization, and limitations.

## Boundaries

No architecture change inside this Work Order.
No alternate execution authority.
No direct provider credential fallback hidden behind a feature flag.
No completeness downgrade to accommodate Aider.
No demo pass based on a partial Aider workflow.
No reimplementation of PPR-018A proof infrastructure inside Aider.
