# PPR-017 — Application Execution Graph, Compatibility Proof Harness, and Demo Mirror Foundation

Status: DELIVERED (merged 327b5b28e1, PR #157, 2026-09-26)
Program: zeck-post-release-public-productization
Authorization date: 2026-09-26
Preferred concurrency: 1 worker
Architecture authority: ACR-006

## Objective

Implement the non-authoritative compatibility/evidence layer defined by ACR-006 so external applications can be audited against one strict AI_EXECUTION_COMPLETE definition.

## Scope

Create machine-readable and executable support for:

- application execution graph inventory;
- execution-surface taxonomy, additive to the existing 22-family capability manifest;
- compatibility evidence record;
- UNASSESSED / PARTIAL / BLOCKED / BYPASS_DETECTED / AI_EXECUTION_COMPLETE status;
- static no-bypass checks;
- runtime direct-provider egress observation/deny controls for proof environments;
- exact application/integration revision pinning;
- mapping of delegated edges to Zeck execution identifiers and evidence;
- Demo Mirror registry and public demo projection.

The implementation must be evidence/projection infrastructure. It is not a new execution, policy, capability, budget, verification or optimization authority.

## Completeness invariants

AI_EXECUTION_COMPLETE is impossible unless every declared material AI execution edge is delegated through Zeck and every delegated edge produces Zeck evidence.

Fixture-only paths, mocks, simulated provider responses, and incomplete application subsets cannot produce AI_EXECUTION_COMPLETE.

The framework must make an omitted material edge visible as a coverage defect, not silently treat it as out of scope.

## Demo Mirror

Add the reusable public website shell for certified application demos. It must support:

- pinned application revision;
- representative task;
- run initiation;
- live execution progress;
- application result;
- Zeck execution timeline;
- route/model/provider/substrate facts when present;
- cost/latency/usage facts when present;
- verification/evidence;
- warnings and limitations;
- baseline comparison when evidence exists;
- reproducibility metadata.

The shell may display PARTIAL/BLOCKED/NOT-RUN demos but must visually distinguish them from AI_EXECUTION_COMPLETE.

## Required tests

- schema/conformance tests for every compatibility object;
- negative test: hidden direct-provider edge cannot be certified;
- negative test: missing edge inventory cannot be certified;
- egress kill test;
- Zeck trace correlation test;
- exact-revision binding test;
- demo status cannot upgrade evidence;
- website route regression tests for the demo surface.

## Required evidence

Create deploy/evidence/ppr-017.json covering:

- exact revisions;
- execution-surface inventory;
- status transitions;
- no-bypass findings;
- representative Zeck trace;
- Demo Mirror route;
- explicit limitations.

## Boundaries

Do not add provider-specific semantics to domain modules.
Do not create a second routing/optimizer.
Do not rewrite the 22-family manifest to make a target application fit.
Do not alter frozen execution lifecycle or RealtimeRail.
Do not classify an application COMPLETE because only its main model path is routed through Zeck.
