# PPR-005 — Test-Harness Convergence Fix (audit-schema forward-apply assertion)

**Status:** AUTHORIZED / WAVE B (correction)
**Program:** zeck-post-release-public-productization
**Base:** current governed main at dispatch
**Origin:** pre-existing defect identified during the PPR-001 delivery cycle (Task 57-b), reproduced identically on clean base 9915be6 by the Lead, independently reproduced and correctly attributed by the PPR-002 worker in an isolated environment (cross-confirmation from two environments); queued then as the first smallest-valid correction candidate.

## Objective

Make the audit-schema forward-apply test track the shipped migration set instead of a stale hard-coded expectation.

## Defect

`tests/integration/postgres/audit-schema.test.ts`, test `0032 applies forward cleanly on the existing authority`: the assertion

```
expect(forward.applied).toEqual([
  { version: 31, name: "isolation_profiles" },
  { version: 32, name: "audit_compliance" },
]);
```

pins exactly two forward-applying migrations, but the shipped set now also carries `0033_application_credentials` and `0034_sandbox_governance` — four apply forward on the 0030-converged base, so the test fails on every clean PG rail that runs the postgres integration suites. The `forward.skipped` expectation and the surrounding comments encode the same stale two-migration assumption.

Live cross-evidence (Lead, 2026-09-21): `deploy:migrate --environment preview` against the real Neon preview authority applied all 33 shipped migrations and converged — the production path is proven; only the test's pinned expectation is stale.

## Fix

Derive the expected forward set from the shipped migration set at runtime (every shipped migration beyond the 0030-converged base, with version and name), instead of the hard-coded pair. The test's intent — "the D-08 migrations apply forward cleanly, no destructive migration, authority rows intact" — must be preserved exactly. Update the stale comments to state the derived expectation.

- full battery per the worker runbook (typecheck, lint, unit, architecture, integration, full suite, governance, deploy:validate) with exact numbers recorded;
- no production code changes (test file only).
