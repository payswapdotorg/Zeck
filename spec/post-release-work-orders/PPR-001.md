# PPR-001 — Discovery-First Console and ShareNet-Inspired Visual Refinement

**Status:** AUTHORIZED / WAVE A  
**Program:** zeck-post-release-public-productization  
**Base:** current governed main at dispatch

## Objective

Reorganize the public Zeck console around first-time user comprehension and capability discovery, using ShareNet's visual/interaction grammar as inspiration while preserving Zeck's own identity and architecture.

## Required surfaces

- discovery/home;
- 22-family capability catalog;
- guided sandbox start;
- primary/mobile navigation;
- result “How Zeck did it” hierarchy;
- Validation Lab entry;
- Trust & Limits entry;
- developer/agent onboarding entrypoints;
- availability/status presentation;
- semantic visual tokens.

## Required behavior

A newcomer must be able to find:
- what Zeck does;
- supported workloads;
- current availability;
- safe sandbox;
- first execution;
- evidence/cost;
- validation;
- agent integration.

Do not require unexplained application/environment identifiers before the user understands the next action.

## Design direction

Use:
- generous whitespace;
- calm neutral surfaces;
- one dominant action;
- state-first hierarchy;
- restrained semantic color;
- compact persistent navigation;
- desktop sidebar;
- mobile bottom navigation;
- active-item treatment;
- progressive disclosure;
- reduced-motion support.

Do not copy ShareNet branding/assets/domain semantics.

## Forbidden

- frozen architecture changes;
- second capability/validation/execution authority;
- provider-specific domain semantics;
- public-contract widening without a separate authorized decision;
- weakening sandbox controls;
- rewriting historical validation evidence.

## Evidence

- unit/type/lint/integration/architecture/governance checks;
- route/discoverability matrix for all 22 workload families;
- desktop/tablet/mobile evidence;
- keyboard/focus evidence;
- reduced-motion evidence;
- before/after discovery journey evidence.
