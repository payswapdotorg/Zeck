## Objective

Produce a real Zeck-complete proof for Cline's material AI execution surface while preserving Cline's IDE/domain capabilities.

## Integration strategy

Pin an exact Cline upstream revision.

Use the existing @cline/llms/provider abstraction and OpenAI-compatible seams where useful, but do not let a generic OpenAI compatibility endpoint hide Zeck-specific execution semantics.

Route every material AI execution edge to Zeck, including any plan-mode, act-mode, vision, reasoning, edit/apply, or auxiliary model calls exercised by the declared corpus.

Cline may retain terminal, filesystem, editor and IDE-specific operations. These remain application/domain capabilities unless an operation makes a direct AI-provider call.

## Proof

Run:

- complete execution-edge inventory;
- provider credential removal from Cline runtime;
- direct-provider egress block;
- representative IDE task corpus;
- Zeck execution/evidence correlation;
- failure/retry/duplicate tests;
- quality, latency and cost-per-successful-outcome comparison;
- customization test;
- determinism/reuse opportunity measurement;
- telemetry review;
- static/runtime no-bypass audit.

AI_EXECUTION_COMPLETE is not awarded for routing only the primary chat model.

## Website demonstration

Register Cline as a real Demo Mirror entry only after its evidence record is AI_EXECUTION_COMPLETE.

The website must launch the actual pinned integration/runtime and expose the corresponding Zeck evidence.

## Boundaries

No frozen architecture change.
No direct-provider fallback in the certified path.
No invented capability family solely for Cline.
No mock execution counted as live proof.
