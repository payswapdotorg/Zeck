# DEP-043 — Production Readiness, Rollback and Provider-Exit Drill

Status: AUTHORIZED / WAVE P4 (dispatch-gated on DEP-040)
Dependencies: DEP-040 (the validated deployment chain); consumes DEP-002 provisioning + DEP-003 release/guardrail/identity machinery
Base: exact current `main` at dispatch

## Objective

Prove the production operations story on evidence: promote a revision to production through the governed release path, verify the deployed plane's identity, roll back with re-attestation, back up and restore the authoritative stores, and execute the provider-exit drill (the documented path off each provider without data loss or domain-authority damage) — through the delivered tooling (`release.ts` promote/rollback with `--plane-url` identity guards, `backup.ts`/`restore.ts`, `provision.ts`/`teardown.ts`, `drill.ts`/`ha.ts` where they apply).

This order drills; it must not redesign the release, backup or provisioning authorities. Defects found in them are reported with reproduction, classification, and fixes only within their own boundaries.

## Credential honesty

Live-provider drills (real Neon/Cloudflare/Upstash operations over the public internet) follow the same env-gated doctrine as DEP-040: with credentials they run for real and record verbatim results/costs; without credentials every live step is honest NOT RUN with owner (Lead credentialed re-run) in `deploy/evidence/dep-043.json`. The LOCAL drills (real local plane processes, real PostgreSQL where a server exists in the environment, real file/object stores) always run.

## Allowed surfaces

`deploy/**` (drill extensions only — no new authority); `deploy/evidence/dep-043.json`; `deploy/PUBLIC-DEPLOYMENT.md` drill-section extensions. No `src/` edits. No console edits — console findings go to the Lead as merge notes.

## Required behavior

- Promote→verify→rollback cycle: a promotion to a verified plane succeeds and journals; a promotion to an unverified/wrong-revision plane refuses (fail-closed, re-proven in the drill context); a rollback re-attests the target revision after the pointer flip.
- Backup/restore round-trip: the authoritative stores' backup restores to an equivalent state (digest-verified where the store carries digests); partial-failure behavior is fail-closed and tested.
- Provider-exit drill: for each provider class in the manifests, the documented exit path (data export, repoint, teardown) executes against the local/available substrate, with the live-provider variant honest NOT RUN where credentials are absent; domain authority is never touched by the exit mechanics.
- Teardown classification guards (defensive re-check) hold under drill conditions: resources are classified before destruction; ambiguous classifications refuse.

## Acceptance criteria

1. The promote→verify→rollback drill runs with both directions' outcomes proven and journaled.
2. The backup/restore round-trip is proven with digest verification and fail-closed partial-failure behavior.
3. The provider-exit drill covers every manifest provider class with honest local verification or NOT RUN boundaries with owners.
4. Teardown guards refuse ambiguous classifications under drill conditions (tested).
5. Any defect: reproduction, root-cause classification, fix within boundaries, regression test.
6. Governance, typecheck, lint, unit, architecture, integration and `bun run deploy:validate` stay green; existing pins stay in sync.
7. `deploy/evidence/dep-043.json` records the verified/notRun split with exact numbers and the drill timeline.

## Required verification

Governance, typecheck, lint, full test suite, deploy:validate, the drill suite (local), hostile negatives (tampered identity at promote, corrupt backup at restore, ambiguous resource at teardown).

## Reporting

Every defect: exact reproduction, root-cause classification, viable solutions, recommended solution with trade-offs, exact verification for closure. Live-drill costs recorded verbatim from provider receipts where rails ran.

Workers do not change `spec/platform-delivery-state/*` and do not merge their own PR.
