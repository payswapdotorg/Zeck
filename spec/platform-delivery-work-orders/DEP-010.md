# DEP-010 — End-to-End Developer Console and Sandbox Playground

Status: AUTHORIZED / WAVE A
Dependencies: none
Base: exact current `main` at dispatch

## Objective
Turn `apps/dashboard` into the complete developer console: application/environment lifecycle, safe credentials UX, execution explorer, capability/provider views, costs/economics, documentation entry points, and a real sandbox playground over the public Zeck API/SDK.

## Allowed surfaces
`apps/dashboard/**`; dashboard-specific tests/fixtures; public-console static assets; minimal public API exposure required only to render existing public contracts; console documentation links.

## Required console surfaces
Home, quickstart, applications, credentials, environments, playground, executions, evidence, artifacts, costs/economics, providers/capabilities, docs and settings.

## Playground requirements
Provide guided runnable examples for text, structured extraction/transformation, RAG, tools/workflows, long-running work, voice/realtime where available, image, video, vision/VLM/audio, multimodal, 3D, browser/computer use and human review. Each capability must clearly show availability/NOT RUN state when live provider access is absent.

Every sandbox execution must use public Zeck integration, synthetic data, hard budgets/timeouts/concurrency/artifact limits and an explicit disposable-sandbox identity.

## Acceptance criteria
1. Fresh developer can reach console, create/select an application/environment and obtain a safe credential without seeing secrets after creation where policy requires.
2. A real sandbox text execution completes through public API and is inspectable end to end.
3. Execution explorer shows result, verification, evidence, activity, route/model/tool/agent/substrate facts and cost where exposed by public contracts.
4. Playground exposes every supported workload family with runnable path or honest unavailable state.
5. Sandbox limits prevent uncontrolled spend and consequential side effects by default.
6. Responsive/accessibility/browser checks pass for all critical flows.
7. No console-local source of truth is introduced.

## Required verification
Typecheck, lint, dashboard tests, public API integration, browser smoke, accessibility checks, sandbox negative tests and exact deployment identity.

Any issue requires reproduction, root cause, viable solutions, recommended solution and trade-offs.
