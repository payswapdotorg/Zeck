# DEP-033 — Accessibility, Responsive Behavior, Security and Cross-Browser Hardening

Status: AUTHORIZED / WAVE P3 (final — dispatch-gated on DEP-030/031/032)
Dependencies: DEP-030, DEP-031, DEP-032 (hardening runs over the completed console surface set)
Base: exact current `main` at dispatch

## Objective

Harden the completed developer console (quickstart, applications, credentials, playground, executions explorer, validation lab, usage dashboard, compare, export) for public deployment: full keyboard paths on every interactive flow, responsive behavior across viewport classes, security hardening of every render and form path, and cross-browser verification — fixing the real defects the hardening pass surfaces, with regression tests that keep them fixed.

This is a hardening order over EXISTING surfaces. It must not redesign the console, introduce a new framework, or create new authorities: it finds and fixes defects in interaction, presentation, security and portability, and adds the regression coverage that pins them.

## Scope of hardening

- **Accessibility**: every interactive element keyboard-reachable with visible focus; labeled controls and honest error states on all forms (issue/reveal/rotate/revoke, composer, rerun forms, lookup); ARIA correctness on tabs, dialogs and live regions; screen-reader sanity on the primary journeys (quickstart → first run; playground choose → compose → run → inspect; validation discovery → rerun; credentials issue → rotate → revoke; explorer navigation).
- **Responsive behavior**: the primary journeys usable across viewport classes (mobile-first verification); tables degrade readably; no horizontal-scroll traps on content paths; touch targets meet minimum sizes on interactive controls.
- **Security**: hostile-value probes over every render path that interpolates user-influenced strings (execution ids, family ids, labels, form values, cookie-derived recents); no reflected markup; no secret-shaped material in any rendered surface; form validation fail-closed; the redaction doctrine (`[not displayed]`) verified on every new path.
- **Cross-browser**: the console's no-script foundation verified (native links, GET forms, details/summary disclosures all work without client.js); the progressive-enhancement layer (client.js) verified not to break the foundation; verification in Chromium plus an honest WebKit/Firefox boundary note where those engines are unavailable in the verification environment (NOT RUN, never assumed-pass).

## Acceptance criteria

1. A keyboard-only operator can complete each primary journey end to end with visible focus and honest error recovery.
2. Primary journeys render and operate across viewport classes without defects; any genuine limitation is recorded honestly with its cause.
3. A hostile-value probe suite covers every render path that interpolates user-influenced input; all probes refused/escaped; zero regressions.
4. The no-script foundation works for the primary journeys; client.js enhances without breaking it.
5. Cross-browser verification is recorded with honest NOT RUN boundaries where engines are unavailable in the environment.
6. Every defect fixed carries a regression test that fails before the fix and passes after (house vitest style).
7. Existing pins, manifests and route counts stay in sync (this order should add no routes; any accidental route is a scope violation).

## Required verification

Governance, typecheck, lint, unit, architecture, integration, keyboard-journey smokes, hostile-input probes, responsive smoke at representative viewport classes, no-script smoke, cross-browser verification with honest boundaries.

## Reporting

Every defect found must include exact reproduction, root-cause classification (Zeck / console / harness / provider / access), the fix, and the regression test that pins it. Aggregate findings are reported even where no code change was required (e.g. verified-clean surfaces).

Workers do not change `spec/platform-delivery-state/*` and do not merge their own PR.
