# DEP-001 — Public Deployment Bootstrap and Free-Tier-First Provider Topology

Status: AUTHORIZED / WAVE A
Dependencies: none
Base: exact current `main` at dispatch

## Objective
Deploy a reproducible public Zeck control/API plane suitable for preview and sandbox exploration, using the existing provider-neutral deployment seams and prioritizing currently valid free/low-cost tiers.

## Allowed surfaces
`deploy/**`; deployment manifests and provider adapters; root deployment configuration; environment/secret references; minimal API startup/config seams required for deployment; deployment tests and docs; deployment identity/smoke tooling.

## Required behavior
- Public API is reachable through a reproducible repository-defined deployment.
- PostgreSQL remains the only durable authority.
- Sandbox/preview uses isolated synthetic data and hard spend/usage guardrails.
- Provider choices prefer free tier, then usage-based/no-minimum, then low fixed cost, subject to capability and terms.
- Vercel Hobby may be used only where terms permit; commercial production must use a permitted plan or alternate host.
- Evaluate Cloudflare Workers/Pages, Neon and R2 first where their current limits fit the workload.
- Provider SDKs remain behind existing ports.
- Exact deployment revision is discoverable and smoke-tested.

## Acceptance criteria
1. Fresh operator can reproduce the target deployment from repository configuration.
2. API health and public integration smoke pass at an exact revision.
3. Environment/credential isolation is proven.
4. Free-tier/low-cost provider choices and exact tested limits are recorded.
5. Quota exhaustion and provider outage fail safely without silent paid overage.
6. Deployment can be rolled back/repointed without changing domain authority.
7. Evidence lists unavailable live-provider checks as NOT RUN.

## Required verification
Governance, typecheck, lint, deployment validation, API smoke, exact deployment identity, secret scans, quota/limit negative paths, and provider-neutrality tests.

## Issue protocol
Any material failure requires exact reproduction, root cause classification, viable solutions, recommended solution with trade-offs, and closure evidence.

Workers do not change `spec/development-state/*` and do not merge their own PR.
