# DEP-012 — Complete Execution Explorer

Status: AUTHORIZED / WAVE B
Dependencies: DEP-010
Base: exact current `main` at dispatch

## Objective

Build the complete execution explorer in the developer console: from an executions list to a full execution detail surface where a developer inspects the complete path of any execution visible to their application scope — result and outputs, verification, evidence and artifact references, activity/events, route/model/tool/agent/substrate facts, costs/usage and provenance — entirely through the existing public contracts.

The explorer is a projection surface. It must not create a second execution, verification, evidence, artifact, cost or event authority: every rendered fact comes from `GET /executions/:id`, `GET /executions/:id/events`, `GET /executions/:id/verification`, `GET /executions/:id/results` and the other existing public records, composed with the dashboard's established inspection vocabulary.

## Required experience

Console navigation: a first-class Executions group reachable from the primary navigation, with the executions list (recent executions opened in this browser and any application-scoped listing the public API exposes) and the execution detail page.

The execution detail surface must present, as tabbed or clearly sectioned views following the established tab-nav pattern:

- **Result** — terminal status, output payload reference, output artifacts with their digest identity, usage summary.
- **Verification** — every verification result recorded for the run: check, outcome, evidence reference; never a re-verification console-side.
- **Activity / events** — the event ledger projection: lifecycle transitions, planning decisions, execution steps, verification and settlement events in causal order.
- **Route & substrate** — the route summary (provider/model where recorded), capability/workload facts, compute substrate and agent/tool participation where the public events carry them, composed with the advanced-inspection vocabulary (`inspection.ts`).
- **Costs / economics** — recorded cost and usage facts from the durable ledger projection; where a fact is not exposed by the public API, state that boundary honestly.
- **Provenance** — application/environment scope, request identity, idempotency semantics, timestamps and any lineage the public records carry.

Every fact that the public API does not expose must render as an honest unavailable state naming the missing public contract — never invented, never approximated from non-public internals. Artifact content is never rendered (references and digests only — the established doctrine).

## Agent/machine parity

Where a machine-readable view of an execution's public facts is natural (for example a JSON rendering of the composed public records), serve it under the console's public routes so a coding agent can follow an execution without scraping HTML. No undocumented UI-only state may be required to understand an execution.

## Honesty rules

- The explorer renders only public-contract facts; the console never becomes a second authority (AC doctrine from DEP-010).
- Missing provider/model/access facts surface as explicit NOT EXPOSED / NOT RUN boundaries with the exact missing contract named.
- Secret-shaped values stay redacted per the serialization-boundary doctrine; no wire shape the explorer renders may carry secret material.

## Acceptance criteria

1. An executions list is reachable from primary navigation showing executions with status, workload family, timing and cost facts the public records carry, with honest empty states for a fresh browser.
2. The execution detail page presents result, verification, activity/events, route/substrate, costs and provenance as distinct, linkable views.
3. Every verification result recorded for a run is inspectable with its outcome and evidence reference.
4. Route/model/tool/agent/substrate facts render from the public event/route summaries using the established inspection vocabulary.
5. Costs and usage render from the recorded ledger facts with explicit boundaries where the public API carries no fact.
6. Artifact references render with digest identity and never with invented content.
7. Facts absent from the public contract render as honest unavailable states naming the missing contract — zero invented data.
8. Responsive, keyboard-accessible, browser-smoke-tested flows; dashboard unit tests cover the new surfaces in the house style.

## Required verification

Governance, typecheck, lint, dashboard unit tests, architecture, integration, browser smoke of the list → detail → tab journeys, and secret-safety probes over the new render paths.

## Reporting

Any defect must include exact reproduction, root-cause classification (Zeck / console / harness / provider / access), viable solutions, recommended solution with trade-offs and the exact verification needed for closure.
