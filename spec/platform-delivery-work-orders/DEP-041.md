# DEP-041 — Fresh-Developer Integration Trial

Status: AUTHORIZED / WAVE P4 (dispatch-gated on DEP-040)
Dependencies: DEP-040 (the validated deployment chain the trial integrates against)
Base: exact current `main` at dispatch

## Objective

A fresh developer integrates Zeck through the public surface with ZERO maintainer intervention: discover the product, authenticate, create an application, configure a sandbox, run a first execution, retrieve results, inspect evidence/costs, list and rerun the validation library, and export a project bundle — following ONLY the human-oriented docs (`docs/developer/`, the quickstart, WORKLOADS.md, TROUBLESHOOTING.md, AVAILABILITY.md) and the public API/console.

The trial is a defect-finding instrument, not a demo: every stumble, dead link, missing prerequisite, ambiguous instruction, naming inconsistency or honest-unavailable surprise is recorded with exact reproduction and root-cause classification (Zeck / console / docs / harness / provider / access). The trial report drives the fixes.

## Trial protocol

- The "fresh developer" persona uses ONLY what the repository publicly exposes to a stranger: the README entry path, docs/developer/**, the console at its served URL, the public API contract. NO reading of src/, specs, internal work orders, or Lead worklogs to figure things out. If the persona cannot proceed, that is a FINDING, not a reason to peek.
- The trial runs against a real locally-booted plane (real processes, real HTTP — the same public contract a hosted plane serves; the identity document is hosting-independent by construction). The public-internet variant against a hosted deployment is the Lead credentialed boundary where no public URL exists.
- The journey: discover → auth → application create → environment/sandbox config → first execution (guided + composed) → results/evidence inspection → costs → validation library discovery + rerun → export/self-host handoff → production-migration docs path.
- Time-box each leg; record where time went. Count every friction event.

## Allowed surfaces

The trial REPORT and its findings are the deliverable. Code changes ONLY for defects the trial surfaces, within the surface that owns the defect (console fixes in `apps/dashboard/**`, docs fixes in `docs/developer/**`), each with a regression test or a recorded docs-verification. `scripts/fresh-developer-trial-dep041.ts` (the reproducible trial script/journey record). `deploy/evidence/dep-041.json`. No `src/` edits — public-contract defects go to the Lead as merge notes.

## Acceptance criteria

1. The full journey completes end to end through the public surface with zero maintainer intervention (or every blocker is a recorded finding with classification).
2. Every friction event is recorded: where, what the persona expected, what happened, the doc/console/API location, reproduction.
3. Each finding carries root-cause classification and either a fix (with regression pin) or a Lead merge note.
4. The trial is reproducible: the script/journey record reruns the same steps against a fresh plane.
5. Honest boundaries: engine/credential/environment limits the trial could not exercise are NOT RUN with owner, never assumed-pass.
6. Governance, typecheck, lint, unit, architecture, integration stay green; existing pins stay in sync.
7. `deploy/evidence/dep-041.json` records the trial's verified/notRun split.

## Required verification

Governance, typecheck, lint, full test suite; the trial script run against a fresh real plane; every fix's regression test.

## Reporting

The trial report separates Zeck defects, console defects, docs defects, harness defects, provider limitations, missing credentials and environmental failures — the roadmap's required-reporting taxonomy.

Workers do not change `spec/platform-delivery-state/*` and do not merge their own PR.
