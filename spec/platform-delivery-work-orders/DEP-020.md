# DEP-020 — Developer and Agent Documentation / Integration Kit

Status: AUTHORIZED / WAVE A
Dependencies: none
Base: exact current `main` at dispatch

## Objective
Create a complete public integration kit so a human developer or coding agent can learn Zeck from the deployed docs and repository alone, integrate through the public API/SDK, run the first sandbox execution, inspect results and migrate to production.

## Allowed surfaces
`docs/**` public developer documentation; API/SDK examples; machine-readable public schemas/capability manifests; `examples/**` and sample application docs; documentation tests/link checks. Do not alter architectural authority or provider semantics.

## Required documentation
- five-minute quickstart;
- conceptual model: Execution, policy, capabilities, budgets, tools, agents, sandbox, verification and evidence;
- authentication and application setup;
- API and SDK reference;
- runnable examples for every supported workload family;
- sandbox usage and limits;
- execution lifecycle and event/result retrieval;
- evidence/provenance/cost inspection;
- provider/model/tool configuration;
- browser/computer/voice/media/3D integration guidance;
- production deployment/promotion and secret management;
- failure taxonomy, troubleshooting and solution playbook;
- provider availability/NOT RUN disclosure rules.

## Agent-readable contract
Publish machine-readable API schemas, capability discovery, request/response examples, environment variable contracts, error codes, rate/usage semantics and deterministic integration recipes. Avoid prose-only critical instructions. Examples must be copy/paste runnable.

## Acceptance criteria
1. Fresh developer can build first successful sandbox integration without maintainer assistance.
2. Fresh coding agent can discover the same integration path from machine-readable docs and examples.
3. Every supported workload family has a concrete example or honest availability boundary.
4. All public examples pass against the supported sandbox path or are explicitly marked provider-gated.
5. Documentation links/schema examples are checked automatically.
6. No secret value is embedded in examples or generated artifacts.

## Required verification
Docs link/schema validation, example compile/typecheck, selected end-to-end public API runs, browser smoke of docs/console links, secret scans and exact revision evidence.

Any material issue requires reproduction, root cause, viable solutions, recommended solution and trade-offs.
