# DEP-040 — End-to-End Public Deployment Validation

Status: AUTHORIZED / WAVE P4 (dispatch-gated on DEP-033)
Dependencies: DEP-033 (the hardened console surface set); consumes the DEP-001/002/003 deployment chain
Base: exact current `main` at dispatch

## Objective

Validate the complete deployment chain end to end as an operator would run it: bootstrap → provision → migrate → identity attestation → full public-route smoke at the exact revision → spend/quota guardrails → release promotion with identity verification — driven through the delivered tooling (`deploy/bootstrap.ts`, `provision.ts`, `migrate.ts`, `identity.ts`, `public-smoke.ts`, `guardrails.ts` via the release path, `release.ts`, `validate.ts`) against REAL plane processes over real HTTP, and against a live hosted plane wherever the required credentials exist in the environment.

This order validates the chain; it must not redesign it. A defect found in the chain is reported with reproduction and root-cause classification and fixed only within the deploy surface's own boundaries.

## Credential honesty (the recorded boundary)

The live-provider rails (Neon PostgreSQL, Cloudflare, Upstash free tiers) need operator-provided credentials — the NOT RUN boundary recorded since DEP-001 and restated by DEP-003. The delivery is structured so that:

- WITHOUT credentials: every locally-verifiable step runs against real local plane processes (real subprocesses, real TCP, real HTTP); every live-provider step is recorded honest NOT RUN with owner (Lead credentialed re-run) in `deploy/evidence/dep-040.json`; nothing is fabricated or assumed-pass.
- WITH credentials (env-gated, presence-checked): the same steps run for real against the live providers, and the evidence records the real results, consumed cost and free-tier assumptions.

## Allowed surfaces

`deploy/**` (verification extensions only — no new authority); `deploy/evidence/dep-040.json`; `docs/DEVELOPER-PLATFORM-DEPLOYMENT-ROADMAP.md` status annotations only. No `src/` module edits. No console (`apps/dashboard/**`) edits — console defects go to the Lead as merge notes.

## Required behavior

- A single end-to-end validation driver composes the delivered tools in the operator's order (the PUBLIC-DEPLOYMENT.md recipe), recording each step's real exit status, timing and output digest.
- The chain runs at an exact revision with the identity attestation verified before and after (drift/tamper fail-closed negatives re-proven in the end-to-end context).
- The guardrail evaluation composes the manifest-carried thresholds per environment class (no hard-coded limits).
- The promote path refuses on an unverified/wrong-revision plane and succeeds on a verified one (both directions driven in the end-to-end context).
- Any failure anywhere in the chain fails the validation — never warns.

## Acceptance criteria

1. The end-to-end driver runs the full chain against real local plane processes; every step's real result is recorded.
2. The credential-honesty doctrine holds: live rails either run for real (credentials present) or record NOT RUN with owner — never fabricated.
3. Wrong-revision/unreachable/unverified-plane negatives fail closed in the end-to-end context.
4. Guardrail thresholds resolve from the manifests; no silent overage path exists.
5. Defects found are reported with reproduction, root-cause classification (Zeck / console / harness / provider / access), fix (within deploy boundaries) and regression test.
6. Governance, typecheck, lint, unit, architecture, integration and `bun run deploy:validate` stay green; existing pins stay in sync.
7. `deploy/evidence/dep-040.json` records the verified/notRun split with exact numbers.

## Required verification

Governance, typecheck, lint, full test suite, the end-to-end driver run (local), deploy:validate, hostile negatives (wrong revision, unreachable plane, tampered identity).

## Reporting

Every defect: exact reproduction, root-cause classification, viable solutions, recommended solution with trade-offs, exact verification for closure. Cost consumed on any live rail is recorded verbatim from provider receipts.

Workers do not change `spec/platform-delivery-state/*` and do not merge their own PR.
