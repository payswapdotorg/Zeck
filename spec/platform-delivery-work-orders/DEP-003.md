# DEP-003 — Production Smoke, Health, Spend/Quota Guardrails and Deployment Identity

Status: AUTHORIZED / WAVE P0 (final — dispatch-gated on DEP-002)
Dependencies: DEP-002 (the provisioning automation the production chain runs through)
Base: exact current `main` at dispatch

## Objective

Close the deployment chain's verification span: the production-grade smoke,
health, spend/quota guardrail and deployment-identity behavior that lets an
operator promote a revision to production on evidence instead of claims. This
order composes DEP-001's bootstrap plane (health/identity endpoints,
public-smoke, manifests) with DEP-002's provision path into the promotion
chain the D-06 release surface already governs — it must not create a second
release, gate or alert authority.

## Allowed surfaces

`deploy/**` (extensions to `public-smoke.ts`, `smoke.ts`, `api.ts` health
paths, `release.ts` gate checks); additive rows in
`deploy/manifests/quota-guards.json` where a guardrail threshold is genuinely
missing; `deploy/PUBLIC-DEPLOYMENT.md`; deployment tests under
`tests/unit/deployment/` and `tests/integration/deployment/`;
`deploy/evidence/dep-003.json`. The closed release-gate vocabulary in
`deploy/manifests/release-policy.json` is NOT widened by this order — a
genuinely required new gate kind goes to the Lead as a merge note. No `src/`
module edits.

## Required behavior

- **Production smoke**: `public-smoke.ts` exercises every public route of the
  deployed plane at an exact revision — health, identity, the executions/
  credentials/sandbox-governance surfaces — asserting the honest-degraded
  boundary semantics already fixed on main (health 200 degraded +
  `--allow-degraded` records the allowed-degraded boundary; authority-
  unavailable fails closed without the flag). A smoke against an unreachable
  or wrong-revision plane fails, never warns.
- **Health**: the production health path reports fail-closed authority
  readiness (database/queue/object-store per the manifests' provider map) with
  degradation classifications proven by real-process probes, not mocks of the
  probe path itself.
- **Spend/quota guardrails**: the enforcement path proves fail-safe on
  exhaustion — quota ceiling hits produce governed refusals (never silent
  paid overage), alert thresholds fire per `quota-guards.json`, and the
  negative paths carry tests. Guardrails bind per environment class from the
  manifests; the tool never hard-codes a limit the manifest does not carry.
- **Deployment identity**: the exact-revision attestation (Git SHA + manifest
  digest + provider topology) is consumed by the promotion path — the release
  gate verifies the deployed plane's identity matches the candidate revision
  before promote, and rollback/repoint re-attests without touching domain
  authority.
- Live-provider promotion rails without credentials record honest NOT RUN
  with owner (Lead credentialed re-run) in `deploy/evidence/dep-003.json`.

## Acceptance criteria

1. A full public-route smoke runs against a real process at an exact revision;
   wrong-revision and unreachable-plane negatives fail closed (tested).
2. Health degradation semantics are proven with real-process probes covering
   the authority-unavailable and allowed-degraded boundaries.
3. Quota/spend guardrail negative paths are tested: ceiling refusal, alert
   threshold, no silent overage; thresholds come from the manifests.
4. The promote path verifies deployment identity before promotion and
   re-attests on rollback; both directions carry tests.
5. No release-gate vocabulary widening occurred (any need is a recorded merge
   note, not a silent edit).
6. Governance, typecheck, lint, unit, architecture, integration and
   `bun run deploy:validate` stay green; existing pins stay in sync.
7. The operator recipe documents the production verification chain with its
   honest NOT RUN boundaries.

## Required verification

Governance, typecheck, lint, unit, architecture, integration (PG suites skip
honestly without `ZECK_PG_TEST_URL`), deployment validation, real-process
smoke runs (health/identity/public routes), guardrail negative-path tests,
identity/rollback verification tests, secret scan, hostile-input probes.

## Reporting

Any defect must include exact reproduction, root-cause classification (Zeck /
console / harness / provider / access), viable solutions, recommended
solution with trade-offs and the exact verification needed for closure.

Workers do not change `spec/platform-delivery-state/*` and do not merge their
own PR.
