# DEP-032 — Project Export, Reproducibility Bundle and Self-Host/Deployment Handoff

Status: AUTHORIZED / WAVE P3
Dependencies: DEP-012 (the execution explorer — delivered), DEP-025 (the Validation Lab's reproducibility bundle — delivered)
Base: exact current `main` at dispatch

## Objective

Extend the reproducibility discipline from the validation program (per-experiment bundles) to the developer's own work: a developer can export a reproducibility bundle for any execution (or a set of executions they have opened) — the composed public records, the task/constraint/metadata identity, the evidence references and digests, the machine manifests revision, and the reproduction instructions — and can follow a documented self-host/deployment handoff path that turns the repository's deployment foundation into a runnable private deployment.

Export is a projection over public records. It must not create a second artifact, evidence or export authority: artifact bytes live in the platform's object store behind digests; the bundle carries references and instructions, never a second copy of authority state.

## Console experience (the projection side)

- From the execution explorer, an export action composes the reproducibility bundle for that execution: the verbatim public facts (the same composition the facts.json machine view serves), the artifact references with digests, the exact repository revision facts the manifests carry, and the reproduction recipe (the integration-kit example or the documented API calls that recreate the run).
- A bundle view + download (or copyable JSON) under the console's public routes; machine parity by construction (the bundle IS the machine view plus recipe).
- The self-host/deployment handoff: a console-linked guide that projects the deployment foundation's real seams (deploy/README.md, the manifests, the bootstrap/smoke tooling) into the developer journey — what a developer needs to run Zeck themselves, what is operator-only, and the honest boundaries (credentials, provider accounts) — without duplicating the deployment docs into a console-local copy that can drift.
- Honest boundaries: any fact the public records do not carry (e.g. environment configuration details) renders as an explicit boundary in the bundle, never approximated.

## Platform side (only what the flows require)

- Additive public routes only where genuinely required (facade pattern); prefer composing from the records the explorer already reads.
- The deployment foundation (deploy/**) is DEP-001's surface: consume its manifests and docs, never edit them; missing projections go through the Lead as merge notes.

## Acceptance criteria

1. A developer can export a reproducibility bundle for any execution visible to their scope, composed from the public records (same composition as the machine facts view + recipe).
2. The bundle carries artifact references and digests only — never artifact content, never a second authority copy.
3. The bundle's reproduction recipe is real (integration-kit example or documented API path) and machine-usable without the console.
4. The self-host handoff guide projects the deployment foundation's real seams with honest operator/developer boundaries; no console-local doc drift.
5. Unit tests (house vitest style) + hostile-value probes; existing pins stay in sync.
6. Machine manifests and the route-count pin stay in sync with any new additive routes (additive rows only).
7. The surface follows the house composed-surface pattern and the honesty doctrine.

## Required verification

Governance, typecheck, lint, unit, architecture, integration, dashboard/browser smoke, hostile-input probes, manifest-sync checks.

## Reporting

Any defect must include exact reproduction, root-cause classification, viable solutions, recommended solution with trade-offs and the exact verification needed for closure.
